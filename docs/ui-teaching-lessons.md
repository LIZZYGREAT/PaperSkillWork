# UI 教学设计复盘与错误记录

> 用途：记录不同论文页面迭代中用户指出的问题和可验证的修正经验。先看「快速查阅」，需要时再读对应的详细记录；每次反馈按日期追加。复用布局和交互经验时，要区分通用规则与论文专属的视觉映射，不机械套用某一页的颜色、尺寸或内容。

> 适用范围：本文已有的 EWC 记录仍按 EWC 的页面内容和视觉语义理解；后续其他论文的经验会单独标明项目，不会覆盖或改写 EWC 专属规则。

## 1. 详细复盘

### 1.1 先画清楚教学关系，不要停在装饰框

**问题表现**

用户强调，页面中央应呈现具体的顺序训练过程，而不是在若干方框里放几行文字。初版视觉需要让人看出输入是什么、模型是否共享、训练后保存了什么，以及新任务到来时究竟发生了什么变化。

**应表达的主线**

```text
Task A Data
     ↓
 Model θ
     ↓
  Train
     ↓
  θ_A*
     ↓
Task B Data
     ↓
继续训练同一个模型
     ↓
 θ changes
```

**修正原则**

- 用图像像素序列、神经网络结构、训练步骤和参数坐标等具体元素表达关系。
- 每幅图先回答“学习者要从这里看懂什么”，再决定是否需要容器、边框、颜色或注释。
- 同一个模型应被看作持续使用的对象；Task B 阶段从已有参数状态继续更新。
- 可以彻底重做教学内容，但不要顺带破坏已经认可的页面框架和 Reference Hub / Hover 交互。

本轮确认的两处文案体现了这种边界：

- **Model θ：**“Task A 与 Task B 继续使用同一个共享模型，并持续更新参数 θ。”避免把所有持续学习设定都说得过于绝对。
- **Task B Data：**“Task B 到来，模型开始针对新的任务数据继续优化。”让读者知道新任务到来后发生的动作。

### 1.2 两种箭头必须分开处理

本轮涉及两组箭头，不能把它们画成同一种布局：

1. **左侧纵向流程节点：**01→02、02→03，依次到 06→07。每一支箭头只连接相邻圆点，不能误做成从 01 一直串到 07 的一支箭头。
2. **训练步骤横向流程：**前向计算 → 计算 Loss → 反向传播 → 更新参数。箭头应水平连接相邻步骤，并与步骤圆心的垂直高度对齐。

**问题表现**

- 连接线和小下箭头被做成容易看出拼接痕迹的零碎部件。
- 07 下方仍有竖线，01 上方也出现短线段。
- 箭头方向、圆心对齐、粗细和箭头尖端位置经过多次返工。
- 曾把“每两个节点之间各有一支箭头”误解成“01 到 07 的一条总箭头”。

**修正原则**

- 先确认节点的排列方向和连接对象，再写样式或计算坐标。表达 `01→02→03` 时，箭头是邻接边，不是整条列表上的一条总连线。
- 纵向连接从当前圆点下沿开始，到下一圆点上沿结束；01 之前和 07 之后都不画线。
- 每支箭头用一条细直线加左右两条短斜线组成清楚的箭头尖端。颜色比辅助线稍深，线条细长，不用粗重的模板箭头。
- 横向训练步骤的箭头要落在圆心高度；需要足够长、清晰，但调整线宽时不要把箭头整体变粗。
- 03 / 06 的训练循环和回环箭头也遵循方向明确、线条轻、头部可辨的规则；不要用太小的默认符号代替明确路径。
- 改完后同时检查纵向时间轴和横向训练步骤，避免只修正其中一类。

### 1.3 字号按角色分层，并检查整页

**问题表现**

部分标签、说明和小注释字号太小，缩放后难看清。只改被截图指出的局部，会让其他区域仍然偏小或字号关系不统一。

**修正原则**

- 建立并复用角色字号：页面标题、区块标题、正文、流程步骤、字段标签、图注/辅助注释。
- 保持视觉层级，但不能为了“辅助信息”而牺牲实际可读性；小标签、图表坐标、颜色图例也要检查。
- 在完整页面和实际视口下检查，不只看组件局部或桌面大屏；移动端尤其要复核。
- 如果某一区块需要放大字体，确认容器、行高和间距也足够，不要只放大文字造成挤压。

### 1.4 留白、区块尺寸和图示边界

**问题表现**

- 01 的数据图示区域空白过多，向量维度少，视觉密度不足。
- 01/05 的 y 标签与像素向量相距过远。
- 各小节的宽度、06 的神经网络图和 06/07 的内容高度不足。
- 07 柱状图边框没有完整容纳所有柱子。

**修正原则**

- 页面区块宽度只需适度增加，让图文有空间；避免为了消除空白而把整页做得过宽。
- 像素序列可以增加维度，让图示更像真实输入序列；同时把 x / y 标识靠近其对应图形，删除无教学意义的空隙。
- 06 的网络图和区块可适当放大、加高；07 也应有足够空间容纳参数组、图例与说明。
- 柱形图的边框、内边距和绘图区必须容纳完整柱体与零轴，不能让柱子贴边、越界或被裁切。
- 一次修改后按 01–07 顺序整体检查，不要只处理被截图标出的那一个区块。

### 1.5 颜色应稳定表达任务和数值

**问题表现**

Task B 数据向量的颜色曾从橙红色变回青色。用户要求 Task B 维持橙红色，仅以深浅区分像素强度。只改其中一个元素的颜色，容易让相同任务的图示出现不一致。

**修正原则**

- 任务类别的色相映射应稳定：本页 Task A 沿用绿色系，Task B 沿用橙红色系。
- 像素强度通过同色系明暗变化表达；不要用换成另一色相代替强弱变化。
- 更新图示时核对整组样本、边框、图例和相关阶段标记，防止局部回归旧色。
- 颜色同时要与旁边的形状和文字语义一致；不要让同一颜色在不同位置暗示相反含义。

### 1.6 输入像素和参数坐标是两种不同的可视化

#### 图像输入（01 / 05）

这些小方格表示图像像素强度序列，不是要求读者逐个解码的二进制向量。格内的 `0` / `1` 会制造错误的重点，也让图形变得拥挤。只用不同深浅表达像素值，并用 x 与 y 标签表示样本和对应目标；Task B 使用橙红色深浅。

#### 模型参数（04 / 07）

这里表达的是固定参数集合在训练前后的取值变化，不能画成参数维度增加或减少。

- 04 的 `θ_A*` 与 07 的更新后 `θ` 必须维度相同、坐标位置一一对应。
- 正负值都应可见，因此柱子以 **0 为中心向上或向下**，而不是全部从底部向上。
- 04 与 07 共用零轴和同一数值尺度；前后柱高可以不同，以表现每个参数值发生了变化。
- 07 保留 04 的淡色旧值 ghost，并在同一参数坐标叠加更新后的值；位置代表参数身份，颜色/高度代表状态和值。
- 当前参数的连续变化应写作 `θ_A* → θ^(t+1) → θ^(t+2) → …`，避免看起来像新建了几个互不相关的参数对象。
- 图注使用“同一参数坐标 · 同一尺度”，不要用含混的“同一刻度”。

### 1.7 Hover、Reference 和教学文案

**语言约定**

- Hover 解释统一使用中文。
- Reference Hub 内的说明统一使用英文。
- 同一组件不要在标题、正文、按钮和注释间无规律切换语言。

**Hover 应提供可用信息**

用户指出，持续学习的 Hover 虽有文字，却没有解释 Task-IL、Domain-IL、Class-IL 分别是什么，也没有说明本页讨论对应哪种任务设置。术语 Hover 至少应帮助读者回答：

1. 这个术语指什么？
2. 相近术语如何区分？
3. 本文/本页实际涉及哪种设置，它与当前教学主线有什么关系？

“这不是某篇论文提出的分类”之类的旁注，如果不能帮助读者区分概念或理解论文，就删掉。不要用正确但无关的免责声明代替定义和关联。

### 1.8 搜索框等小型 UI

搜索条被指出不需要红色边框，并且提示文字应为英文。类似局部反馈应检查组件的完整状态：默认、聚焦、输入中和无结果状态。边框颜色可以帮助聚焦，但不能未经要求套用醒目的红色；可见文案遵循本项目的语言约定。

### 1.9 修改范围要清楚

本轮用户允许全面重构教学内容，同时明确基本页面框架、Reference Hub 和 Hover 机制可以保留。后续遇到类似任务时：

### 2026-10-03｜iCaRL Page 3 类内点距、原型遮挡与簇分隔

**问题表现**

- 用户要求三类样本点彼此拉开、点径稍小，并利用绘图区空白。首次修订把点距诉求误当成整图放大；之后仅围绕均值统一扩大点云，仍留下贴近均值的样本点。
- 类均值标记和个别样本点相互遮挡；三类点云的边界不够清楚。表示更新阶段的旧均值文字也靠到点上，query 与最近原型的符号过近。

**原因或误判**

- 把点的半径、绘图区整体缩放和样本之间的实际距离混成一个“看起来更大”的问题。改变 viewBox 只改变整张图的显示比例，不会增加点相对于类中心的间距。
- 对样本偏差统一乘倍率虽保留均值，却也保留了“本来就在均值附近”的样本；没有先检查每个类中心到最近样本点的距离。
- 初次验收只看点云总体包围范围，没有同时检查类内间距、中心到样本间隔、类间空隙、符号/文字碰撞和 φnew 映射后的结果。

**修正原则**

- 把反馈转成四项分别可见的验收条件：样本点略小；同类点彼此可辨；每个样本与本类均值符号分开；蓝、绿、橙三类点云之间留有清楚空隙。不得用放大整图替代调整点位。
- 不改变未被要求修改的原型中心、query 位置和分类数值。固定合成样本可采用围绕均值的成对对称偏移，使类均值保持不变，同时保证没有样本落在中心符号上；控制云团半径，避免相邻类别靠拢。
- 按碰撞结果缩小数据点、中心或 query 标记；移动旧均值标签到空白处。绘图坐标、点大小和标签位置需要分别调整，避免一种改动掩盖另一种问题。

**复查方式**

- 在浏览器中查看三类同时出现的阶段，确认每个均值周围都没有样本点遮挡，三簇边界清楚，所有点均在绘图区内。
- 查看 query 最近原型阶段和 φold→φnew 移动阶段，确认 query、原型、样本、旧均值文字不会互相压住；再看均值重算阶段，确认中心仍对应当前样本。
- 复核类均值、query 距离与预测值保持不变；在实际浏览器视口检查完整图形和图例，而不是只依据源码或局部组件截图判断。

### 2026-10-03｜iCaRL W8 一致性、术语入口与参考层

**问题表现**

- W8 审计要求同时区分论文结果、作者解释、教学说明和通用数据集背景；Hybrid 3 与 LwF.MC 的对比会同时改变 exemplar 回放和蒸馏，不能写成只改变一个变量的干净消融。
- Page 3 与 Page 10 必须使用同一组示例样本身份和归一化几何；学习者看到的类别编号应是 1–4，训练集符号 D 仍代表数据集合。
- Page 1 在任务设定尚未展开时直接露出 Feature Extractor φΘ；术语只在 Page 9 的局部 Reference Hub 中有入口，其他页面第一次看到关键术语时无法继续查阅。
- iCaRL 的参考面板比 EWC 窄，列表和详情文字显得拥挤；术语速览更窄，鼠标从术语移动到弹层时弹层会关闭。Page 7 的目标矩阵在窄屏也会把各列压到难读。
- 少数移动端标签、图表标注字号低于 10px；若只检查桌面正文，难以发现这些低可读性的语义文字。

**原因或误判**

- 把论文描述中的相邻方法差异简化成单一机制变量，没有并列核对每个比较方法包含的机制。
- 把原始样本身份、二维投影位置和归一化后的分类几何分别维护，或用字母类名展示内部示例，增加了跨页映射成本。
- 把术语 Hover 当作完整解释，且默认采用通用参考组件尺寸；没有对照 EWC 实际使用的宽抽屉、分栏与正文比例，也没有处理指针在触发词和弹层之间移动的过程。
- 字号逐条局部调整，未按语义角色扫描所有页面和断点；表格只按桌面宽度设计，没有预留窄屏横向查看方式。

**修正原则**

- 组件对照必须写清两种配置分别启用的机制。若一对方法同时改变多个机制，标为 contrast pair 并限制归因；只有控制其他组件后的比较才称 cleaner controlled comparison。数据集背景来源与论文实验结论分别标记。
- 跨页样本以同一 canonical ID 和坐标/归一化过程为准；显示给读者的类别编号为 1–4，D 只代表本轮训练集对象。Page 1 先解释类别增量学习与遗忘问题，在 Page 2 再正式引入 φΘ。
- 术语第一次出现时用可交互入口连接全局 Reference Hub；Hover 提供简短中文定义、本文作用与易混点，Reference 的条目与界面文案保持英文。可参照 EWC：桌面右侧宽抽屉接近 980px，列表/详情并列且各自可读；正文约 15px、行距 1.7。术语速览宽约 420px，正文字号约 15px；触发词离开后延迟关闭，让指针可移入弹层，键盘焦点仍可操作。
- 窄屏复杂矩阵应保留列结构并提供独立横向滚动区域，且区域可键盘聚焦；不要把列压到无法辨认。全局检查语义文字，字号至少 10px；仅用于排序或识别的装饰小标记可例外。
- W8 构建和机械检查不能代替 W9 人工学习与证据审阅；没有实际浏览器视口复核时，不记录为已完成视觉验收。

**复查方式**

- 对照论文表格和每个方法的组件定义，逐项复查 Page 9 的对照类型、机制变化和结论范围；确认 CIFAR/ImageNet 通用背景引用没有被标成论文实验结果。
- 追踪同一 canonical 样本在 Page 2、3 和 10 的身份及表示状态；查看面向学习者的类名为 1–4，D 没有被当成类别或模型参数。
- 从 Page 1–10 首次出现处逐页开启术语 Hover，并从其中打开同一个 Reference Hub；在 EWC 同等桌面宽度检查抽屉两栏、正文、颜色和来源，在窄屏检查抽屉与 Hover 的换行和边界。
- 将 Page 7 缩到窄视口，确认目标矩阵只在自己的横向滚动区域移动，整页不产生意外横向滚动，Tab 聚焦后可查看全部列。
- 本轮通过 TypeScript/Vite production build 与 `python tools/paper.py check icarl` 的机械检查；没有完成真实浏览器截图复核。检查结果仍显示 W9 与 W10 为 PENDING，不能将其记作学习或发布验收通过。
