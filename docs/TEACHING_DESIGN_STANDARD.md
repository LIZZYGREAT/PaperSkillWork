# 通用教学设计规范

本规范适用于 PaperSkillWork 中所有论文项目的教学设计。它约束叙事、表达方式和交互取舍，不规定论文页面的固定版式，也不替代原论文证据、项目级 W4/W5 决定或人工验收。

## 1. 依据与边界

- 原论文与 evidence registry 决定论文事实、数学含义、实验条件和可支持的结论。
- 已确认的项目级 W4/W5 设计决定该论文的教学顺序、页面选择和视觉语义；通用规范提供默认原则，不推翻已批准设计。
- CORE 内容必须在主线中可理解。交互、构建、截图和机器检查都不能替代 W7/W9 人工学习与证据判断。
- 规范是设计审查工具，不是要求每一页使用相同字段、卡片或组件的页面 schema。

## 2. W4：让概念由问题自然引出

教程面向有一定计算机基础、但不了解目标论文与研究方向的读者。教学主线从已有任务、读者已有认识和当前真实约束出发，按“已有认识 → 当前不足或新问题 → 自然的探索思路 → 论文采用的机制 → 机制实际效果与下一问题”推进。这是审查推演是否连续的框架，不是每页必须出现的五个标题或五张卡片；教学推演是面向读者的合理解释路径，不得冒充作者未声称的历史发现过程或论文结论。

对每个 CORE 阶段，审查者应能回答：

1. 读者此前已看到什么事实、数据或运行状态？
2. 现有方法或表示在哪一点上不足？
3. 现在引入什么机制或术语，为什么它适合解决这个缺口？有多种路线时，应说明论文的选择理由，不得把选择写成数学必然。
4. 哪个对象、变量、分布或状态发生变化？为什么？
5. 读者能从页面或交互中观察到什么，并由此提出什么尚未解决的问题？

这五项用于检查论证连续性，不要求变成五张卡片或重复出现在正文中。术语第一次进入主线前，应先让读者看到需要命名、计算或解释的对象。不要为了“知识完整”提前塞入尚未需要的术语、组件或数学工具。只在一个主要位置完整教授一个概念；后续只有产生新角色、机制关联或深化需要时才补充，否则以轻量引用式回收恢复必要上下文。推导和背景可放在 Supporting 或 Reference，但主线真正依赖的解释不能被移出正文。

页面应承接上一阶段的已知条件，并在读者可能忘记上下文时提供简短回忆线索。可从直觉或最简单的自洽系统开始，但应说明暂时假设和省略的难题，并在讲解完整运行过程时恢复真实执行顺序。不可为压缩篇幅而删掉引出机制所必需的因果转折。

引导文案本身也是推演的一部分：长引导可拆成与动画或步骤同步的短段，逐段突出当前问题、已有条件、方法和转折；不得把它压成脱离上下文的概念摘要或术语清单。叙事可以沿“回忆已有条件 → 提出问题 → 形成直觉 → 引入机制 → 观察计算 → 引出下一问题”推进。

### 两种完整性与算法贯通

- **认知完整性**：关键机制出现时，读者已有足够前置认识，并明白为什么此处需要它。
- **执行完整性**：教程结束时，读者能够依据已学机制，还原 W2 中从输入和初始化，经训练轮次、状态交接、关键分支与计算，到预测/输出的真实算法。

W4 必须安排至少一个专门的完整算法贯通环节，位置和长度由论文的实际教学逻辑决定。该环节通常不承担大规模新概念的首次教学，也不重复前文的整套推导；它以 W2 的 Algorithm Execution Model 为依据，强调对象身份、数据流、调用与更新时间、跨轮持久状态和最终输出。完整贯通必须被重新组织为一个系统级教学场景，不能仅把前面页面的组件、公式和动画依次拼接便视为完成；低层计算、原子图形或素材可以复用，但整体关注点和跨阶段衔接要服务于完整系统理解。

## 3. W5：明确文字、图形与交互各自的任务

| 表达方式 | 主要任务 |
| --- | --- |
| 自然段 | 解释问题、因果、设计选择和结论 |
| 静态图 | 显示对象、结构、归属及变量关系 |
| 对比图 | 固定关键不变量，突出变化及其后果 |
| 交互 | 改变可核对的教学变量，让读者检验 If/Then |
| 动画 | 显示时间、顺序、状态或信息传递 |
| 公式 | 精确给出关系；正文仍需解释引入理由和含义 |

核心板块的文字与对应图形或交互应靠近并相互指代。一个普通段落不必强行配图；静态图已清楚表达时，也不必增加重复说明。每种主要视觉表达都应有明确学习任务。交互所用数值和图表应共享可追溯的数据或计算逻辑。

W5 先根据教学任务确定主视觉、空间关系、信息层级和状态转场，再查看 Kit 来选择可复用的部件；Kit 不应替场景决定构图。对承担核心机制或高风险系统关系的动态主场景，在实现前审看高保真关键帧和短动态原型，或能准确表达动作与时间关系的分镜。只对这类关键场景要求原型，不为普通页面套模板，也不要求所有页面采用动画。

对于有真实计算步骤的机制，优先让读者看见对象从哪里来、经过什么运算、为何被选中，以及哪些状态被保留；主视区可用运动和几何关系说明机制，精确公式、逐点数值和完整表格可放在按需查看的详情中，但不能因此删掉数学依据。页面应保持一个稳定的主要观察焦点，让当前引导、主图和控制之间的关系容易追踪；目标宽屏下不应要求横向滚动页面来阅读主线。

流程线和箭头表达具体关系：方向、端点和相邻步骤必须对应实际对象与过程；时间顺序、数据流、读写和解释性关联不能画成同一种含混连接。布局或视口改变后，应复查端点是否仍落在预期对象上。

颜色可以表达类别或状态，但关键识别不能只依赖颜色；需要时同时使用文字、形状、线型或标记，并保持同一颜色语义在相关视图中稳定。应在实际背景与代表性状态下复核文字、细线和辅助标签的对比度。

短问题引入、机制解释、比较结论、章节衔接和可展开推导可以作为视觉写法参考，而不是固定组件。先使用现有语义化 HTML、CSS 规则和 tokens；只有跨论文存在明确重复行为时才抽成共享组件。不要为每种文案样式增加一层运行框架，也不要把某篇论文的教学结论写入通用 Kit。

## 4. 文字、数学与术语参考

- 字体层级按语义角色维护：标题、正文、图内标签、辅助说明和来源信息应容易区分；关键机制不得只放在难以辨认的小字中。具体字号由项目主题和真实渲染决定。
- 普通句子和简单记号按自然文本排版；简单上下标应在同一局部保持一致。分式、求和、矩阵、复杂指数和推导使用 KaTeX 或等价的数学排版方式。
- 不为追求公式覆盖率把自然语言拆成许多公式容器。长公式应换行或允许在公式局部横向查看，不能造成页面整体溢出。
- 数学工具在问题真正需要时引入，并说明它在当前机制中解决什么困难。复杂但必要的数学可以使用较大篇幅、详细推导和复杂交互；其问题不在复杂，而在出现时机和解释目标不清。
- 核心复杂表达可先建立直观意义，再从 `k=2`、`k=3`、显式求和、简单代入或几何关系展开，最后回到一般形式。选择展开层次应服务理解，不得把核心数学全部藏入参考区或堆成公式墙。
- Hover 与 Reference Hub 使用同一 canonical term ID 关联短说明和详细资料，但可按项目设置不同语言与长度。Hover 只解释术语、本文作用及必要的易混点；Hub 可提供背景、来源和交叉引用。正文必须包含主线所需的关键论证。
- 不在标题、卡片、图注等多个位置重复同一免责声明或普通示意数据说明。只在容易误解的内容旁清楚说明一次。

文字负责解释因果、问题、选择理由和观察结论，不把完整推理压成标签清单；图形负责帮助理解结构、关系和变化，但复杂图形仍须有阅读指导；伪代码负责真实操作顺序、变量来源、状态生命周期以及训练/推断区分，不能被概念流程图替代。数字、表格与“教学示例”免责声明只在确有数据价值或误解风险时出现，不为形式完整机械堆叠。

## 5. 连续身份、可观察计算与示例边界

- 同一对象跨页面和状态应保留可追踪的身份。若表示或坐标系发生转换，应说明对应关系；不要通过重建一批不同对象来伪装连续变化。
- 讲解计算过程时，让图形、文案、进度和数值由同一权威状态派生。重要运算应能观察到真实的中间结果；不得让动画声称正在计算，而图上早已显示最终答案。
- 图形、公式、表格和交互应使用一致的数据与计算。真实论文数据、论文结果、教学假设和合成示例要明确区分；不得为视觉效果改动真实输入、参数、选择结果或计算值。
- 合成示例应能由所展示的规则重算，并在容易误解处标注为教学示例。不得把合成坐标、玩具计算或示意轨迹说成论文实验数据或真实模型训练轨迹。
- 对象身份、输入、状态更新、输出和向下一步的交接要能从画面中追踪；适用时区分持久状态与临时状态、可学习参数与计算量，以及训练过程与推断过程。

## 6. 动画与设计变更

保留、合并或删除动画前，说明它新增的认知价值：用户改变什么、哪些对象发生什么变化、什么属性必须固定，以及静态图或交互为什么不足以解释该关系。动画应有清楚初态、同步反馈、暂停或重置方式、reduced-motion 支持；关闭动效后仍能理解机制。讲解算法动画时，先交代输入、已有状态和目标，再展示公式代入、候选形成、结果比较与状态更新。重复迭代可先完整演示一轮，再适度加快后续轮次；重要中间结果应停留到可以观察，不要在短时间内闪过多个因果动作。播放节奏不得打断关键观察。

实现需要动画的场景时，先让核心动作、身份连续性和状态交接忠于同一计算模型，再独立精修版式、字体、线条、色彩与装饰；精修后重新检查运动端点、对象归属和节奏。静态表达更清楚时就保留静态。W7/W9 人审分别判断运动表达是否清楚、算法语义与证据是否准确、教学因果和读者理解是否成立，再综合评价；这不是由 Agent 打分的动画量表，也不设动画数量或时长目标。

已确认的结构、数值、颜色语义、对象身份、尺度、状态和连接关系视为不变量。常规改动先登记目标、允许修改范围、受影响区域和需保护的不变量，并复查相邻页面或状态。改变 CORE 顺序、算法含义、主工作台结构或已批准动画属于设计调整，应先取得用户对取舍的确认。低风险排版修复可以按既有设计直接实施。

项目级 W4/W5 设计与变更记录保存在现有 learning-spine 和 implementation-plan 中；不要为同一决定另建平行的页面契约文档。实际截图与浏览器检查按 docs/VISUAL_QA.md 执行。
