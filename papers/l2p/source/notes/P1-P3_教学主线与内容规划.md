## 一、前三页的整体任务

前三页按照**研究约束 → 已有模型的完整结构 → 模型内部的计算机制**推进，目的是为 P4 引入 Prompt Tuning 建立充分的技术前提。

```text
P1 连续学习：为什么需要新的适应方式？
    已有分类模型 + 顺序到来的新类别
       → 参数持续更新可能损害旧类别预测
       → 旧样本未必可用，测试时又不知道任务 ID
       → 考虑利用已经预训练好的视觉模型
                         ↓
P2 ViT：预训练视觉模型究竟如何处理一张图片？
    图像 → Patch → 图像 Token + [CLS] → Encoder 堆叠
       → 输出包含上下文信息的 Token 表示
       → 形成整张图片的分类特征
                         ↓
P3 Transformer：Token 之间的关系怎样被计算？
    一层 Encoder 的输入 Token
       → Q/K/V → Attention → Multi-Head → 残差、LayerNorm、FFN
       → 更新后的 Token 进入下一层
       → 冻结权重时，输入 Token 的改变仍能改变输出
                         ↓
P4 Prompt Tuning：能否学习额外 Token 来适应新任务？
```

这三页不是三段相互独立的基础知识介绍。P1 最后交出“已有预训练模型值得利用”的问题；P2 交出“Token 为什么会获得全局信息”的问题；P3 交出“能否通过额外的可训练 Token 改变冻结模型的行为”的问题。后页必须直接接住前页留下的对象与疑问。

### 对前三页的内容约束

- **以真实模型对象为主**：同一张示例图像、Patch、Token、ViT、Encoder Block 在页面之间保持身份关系；不靠故事化隐喻讲解网络。
- **先有整体，后进入内部**：P2 先展示完整 ViT 网络，再局部放大；P3 从 P2 中实际存在的一个 Encoder Block 展开，而非重新画一套不相干的结构。
- **复杂处讲透，非关键处暂时保留黑盒**：解释 Attention 的必要计算、Transformer Block 的执行关系；不在前三页展开 L2P 的 Key–Prompt Pool、Top-N 和联合损失。
- **区分论文事实与通用基础知识**：连续学习设置、L2P 对预训练 ViT 的使用来自论文；Pre-LN Block 方程、ViT-B/16 的典型层数等属于前置架构解释，按具体模型实现核对，不宣称这些是 L2P 创新。
- **视觉服务推理**：每一处图形、交互或运动都应回答本页的一个可检验问题。没有必要为三个页面分别制作完整大型动画。

## 二、P1：连续学习的研究背景与任务约束

### 1. 页面要解决的问题

读者进入时已知道：一个图像分类模型可以通过训练数据更新参数，并根据输入图片输出类别。P1 需要让他理解：**当数据不再一次性全部提供，而是按任务顺序到来时，为什么持续训练会产生新的困难？L2P 具体要满足什么约束？**

这一页的终点不是解释 L2P 的方法，而是使读者愿意继续了解“已有预训练视觉模型能提供什么基础能力”。

### 2. 主线内容及其展开顺序

**（1）先建立最小的分类系统。**

从一张图像 $x$、一个分类网络 $f_\theta$ 和分类结果开始。模型经过训练后具有识别若干类别的能力。只需让读者知道输入、预测、标签与参数更新存在关联，不重新讲授梯度下降。

**（2）改变数据条件：新任务依次到来。**

用原论文的 Split CIFAR-100 作为明确的实验背景：100 个类别按 10 个任务组织，每个任务包含 10 个互不重叠的类别（Appendix C）。例如先训练任务 1 的类别，再接收任务 2 的新类别。下一阶段训练时，先前的原始训练图像可能不可访问；基础 L2P 不依赖保存旧样本进行重放。这里的任务划分用于解释训练数据到来的顺序，不代表测试时会提供任务编号。

**（3）观察同一网络的状态被后续训练改变。**

初始模型经过任务 1 的训练得到 $\theta_1$，继续用任务 2 的训练数据更新为 $\theta_2$。由于新旧类别使用共享的可训练参数，服务于新任务的更新可能改变旧类别的输出，形成灾难性遗忘。建议用同一张旧类别测试图像对照“训练前后预测”，但其具体分数必须是明示的合成教学示例，不能伪称论文记录的真实梯度轨迹或准确率。

**（4）明确最终需要达到的预测目标。**

在类别增量学习中，测试图像可能来自已经学习过的任一类别，且没有任务 ID。模型需要在统一的已学类别空间中完成分类。任务 2 的训练结束，不意味着只测试任务 2，也不意味着系统可以选择一个按任务划分的专属分类头。可以简短点出：论文还研究领域增量与无明确任务边界的 task-agnostic 场景，但不在这里展开全部协议和数据集细节。

**（5）提出论文采用的研究切入点。**

面对主干反复更新引起的干扰、旧数据可能无法回放，以及测试时不知道任务 ID 的条件，作者提出利用一个**已有良好表征能力的预训练模型**，保留其主干参数，通过较小的可训练结构实现后续适应。此处只揭示“冻结主干、将适应能力转移到少量参数”的方向，暂不介绍 Prompt Pool 的具体结构、检索与训练公式。

### 3. 本页核心视觉与表达分工

**主视觉：同一个图像分类模型贯穿任务时间线。**

画面中应始终保留同一个网络与固定身份的旧测试图像。任务 1、任务 2、任务 3 是按时间进入的训练数据；在需要的时刻，旧测试图像重新经过当前模型，产生可观察的预测变化。这样读者能直接把“参数从 $\theta_1$ 变为 $\theta_2$”与“旧类别预测可能改变”联系起来。

- 图形：输入图片、神经网络、类别输出、按时间排列的任务数据、旧类别测试入口。
- 动态或交互：切换到下一任务训练阶段，再用同一旧图查看预测变化；若不采用真实训练仿真，应明确只是可复算的教学状态演示。
- 正文：解释连续学习的约束、共享参数冲突和测试任务 ID 不可用的意义。
- 暂不出现：Q/K/V、Prompt Token、Key–Prompt 配对、余弦检索、L2P 的总损失。

**阅读完成后的认识**：读者知道研究问题来自顺序训练与统一预测的冲突，并理解为什么下一步值得考察预训练视觉模型本身，而不是立即讨论某个尚未定义的 Prompt 组件。

**交给 P2 的问题**：预训练视觉模型到底由哪些部分构成？它如何把原始图像转换成可供后续机制利用的特征？

## 三、P2：Vision Transformer 的整体架构与输入输出

### 1. 页面要解决的问题

P1 已经引出“保留预训练模型的基础能力”。P2 必须把此前只是一个黑盒的分类网络展开成**可定位、可追踪、具有清楚层级关系的 ViT 神经网络**。读者离开本页时，至少能够指出图像经过哪些主要阶段、Token 在哪里形成、Transformer Encoder 如何堆叠、输出特征从哪里得到。

### 2. 主线内容及其展开顺序

**（1）先展示完整 ViT 的端到端架构。**

主图应首先给出：原始图像 $x$ → 图像 Patch → 线性嵌入及输入表示 → Token 序列 → 堆叠的 Transformer Encoder Blocks → 最终 Token 表示 → 分类读出。用明确的边界标示预训练特征模型的两个部分：输入嵌入 $f_e$ 与 Encoder 堆叠 $f_r$，组成 $f=f_r\circ f_e$。原论文 L2P 将最终分类头与这套冻结特征主干分开表述。

**（2）沿主图向左展开“图像为什么要变成 Token”。**

说明 Transformer 处理的是向量序列，而输入是二维图像。以论文实验中的 $224\times224$ 图像、ViT-B/16 的 $16\times16$ Patch 为例，得到 $14\times14=196$ 个图像 Patch。每个 Patch 展平成向量，经嵌入映射得到一个 $D$ 维 Token。典型 ViT-B/16 使用 $D=768$；添加用于整体表示的 `[CLS]`，输入序列长度为 $L=197$。位置编码承担位置区分的作用。可使用

$$
X_e=f_e(x)\in\mathbb R^{197\times768}
$$

概括最终交给 Encoder 的图像 Token 序列，而不将特定实现中位置编码的插入顺序误写为 L2P 论文自行规定的步骤。

读者需要看清**196 个 Patch 与 196 个图像局部 Token 的对应关系**，以及 `[CLS]` 是另外一个用于整体表示的特殊 Token；197 与 768 分别描述序列长度和每个 Token 的特征维度。

**（3）回到整体架构，认识 Encoder 的层级堆叠。**

图中从一个输入 Token 序列出发，依次经过多层 Encoder。每层输出仍是 Token 序列，但其中的特征随计算而变化，并成为下一层输入。对典型 ViT-B/16，可以用 12 层作为真实的网络尺度参照；不需要在画面中绘制 12 组庞大重复的内部节点，而应通过精细的层叠结构、层编号与一处 Block 放大入口清楚表达。此处先建立一个 Block 包含 Self-Attention、MLP/FFN、LayerNorm 和残差连接的**整体轮廓**，其内部原理留给 P3。

**（4）解释网络输出如何形成分类特征。**

在普通 ViT 分类背景中，最后一层 `[CLS]` 位置的特征可以用于全图分类。它之所以能表示整张图片，依赖 Encoder 内部的跨 Token 信息交互；这一点先陈述观察目标，不直接跳到结论。此处不要将普通 ViT 的分类读出偷换为 L2P 的最终分类方式：原论文中，未加 Prompt 的 `[CLS]` 特征用于后续 Query 提取，而 L2P 带 Prompt 的分类前向采用 **Prompt 位置输出的平均池化**，将在后续方法页单独解释。

**（5）引出关键尚未解释的机制。**

如果一个 Patch Token 起初主要表示一块图像区域，那么经过多个 Encoder 后，它为何能够包含来自其他位置的上下文？`[CLS]` 又如何汇集全图信息？这需要打开一个 Encoder Block，观察 Self-Attention 的计算。

### 3. 本页核心视觉与表达分工

**主视觉：一张完整、精修的 ViT 架构图，并允许局部放大。**

- 主图显示清楚的物理顺序：图像 → Patch 分块 → 嵌入 Token → `[CLS]`/位置 → Encoder 堆叠 → 输出序列与读出。
- 选中图像上的某个 Patch 时，应在右侧对应的向量和 Token 上显示同一身份；不能用毫无语义的随机节点连线代替图像到 Token 的映射。
- 堆叠图要让读者看见一个 Block 的输出如何成为下一 Block 的输入。完整堆叠负责交代尺度与系统位置，局部放大负责解释组成，避免在同一画面同时展开 12 层的全部 Attention 细节。
- 可将 `f_e`、`f_r` 的范围与冻结状态提前标识，为 P3 和 P4 保持一致的视觉语言；冻结指**参数不再更新**，不是模型没有计算或输出不会变化。

**阅读完成后的认识**：读者能够从原图追踪到 $197\times768$ 的 Token 序列，理解 Encoder 的重复结构，知道 `[CLS]`、Patch Token、输入嵌入和输出表示各在何处，也知道后续讨论的冻结预训练主干是哪些实际模块。

**交给 P3 的问题**：同一个 Encoder Block 内，Token 之间究竟怎样交换信息？这些操作如何组成一层完整的 Transformer？

## 四、P3：Attention 与 Transformer Encoder 的真实计算机制

### 1. 页面要解决的问题

P2 已展示 Encoder 的存在和层叠关系；P3 要打开其中**一个真实 Block**，从输入 Token 开始解释一次计算，再回到多层堆叠。最终借助已建立的计算原理解释：**权重冻结并不意味着输出与输入无关，改变输入 Token 仍可能改变最终特征。** 这一结论直接支持 P4 的 Prompt Tuning。

### 2. 主线内容及其展开顺序

**（1）承接 P2 的输入 Token，建立一次注意力计算的对象。**

固定一个简化的 Token 序列 $Z\in\mathbb R^{L\times D}$，可从完整的 197 个 Token 中选出 `[CLS]` 和少量 Patch Token 做局部教学演示，但必须说明这是局部放大，真实网络仍处理完整序列。先说明单个 Token 拥有自己的当前向量表示，而输出能从其他 Token 获取信息，需要一套匹配和聚合规则。

**（2）展开 Self-Attention：从 Q/K/V 到新的 Token。**

在一个 Attention Head 内，输入序列经三组线性投影生成

$$
Q=ZW_Q,\qquad K=ZW_K,\qquad V=ZW_V.
$$

对某个目标 Token $i$，它的 Query 与所有来源 Token $j$ 的 Key 计算匹配分数，除以 $\sqrt{d_k}$ 后经 Softmax 得到权重 $a_{ij}$，再对来源 Value 加权求和：

$$
a_{ij}=\operatorname{Softmax}_j\left(\frac{q_i^\top k_j}{\sqrt{d_k}}\right),
\qquad o_i=\sum_j a_{ij}v_j.
$$

这里要让读者真正看见三个阶段：**匹配分数形成 → 权重归一化 → 根据权重聚合 Value**。建议先固定 `[CLS]` 为目标 Token，观察它读取不同 Patch 的信息，再切换目标 Token 以说明所有位置都可以更新。演示值应有统一的数据源和可复算的数学关系，避免任意跳动的数字或没有对应运算的动态连线。

**（3）从单头扩展到 Multi-Head Attention。**

说明不同 Head 具有各自的 $W_Q,W_K,W_V$，产生不同的聚合结果；各 Head 的输出拼接后通过输出投影回到模型隐藏维度。这里的重点是**多头计算怎样汇回一个新的 Token 表示**，无需额外讲述所有参数量、复杂度或其他 Attention 变体。

**（4）把 Attention 放回完整 Encoder Block。**

以典型 Pre-LN Block 的教学形式展示两次子层处理与残差连接：

$$
\begin{aligned}
U &= Z+\operatorname{MSA}(\operatorname{LN}(Z)),\\
Z'&=U+\operatorname{MLP}(\operatorname{LN}(U)).
\end{aligned}
$$

解释 LayerNorm 位于当前子层的输入侧；MSA 在不同 Token 之间聚合信息；MLP/FFN 在每个 Token 的特征维度上进行非线性变换；残差连接把子层输入与其输出相加。应在同一幅 Block 结构图上逐段追踪 **$Z\rightarrow U\rightarrow Z'$**，使每条残差支路的起点、终点和对应相加节点清楚。以上表达是常规 Pre-LN 架构的前置说明，具体归一化次序以所选 ViT 实现为准。

**（5）回到 P2 的层叠网络，说明信息如何持续传播。**

当前 Block 的输出 $Z'$ 成为下一 Block 的输入。经过多层重复计算，Token 的表示反复吸收上下文信息；这说明图像局部 Token 与 `[CLS]` 可以形成更丰富的全图表示。这里主要强调**连续的状态递进**，不暗示每一层都必然产生某种人工指定的语义特征。

**（6）收束到冻结参数与可变输入的关系。**

将同一个 Transformer 的权重固定，比较不同输入序列下的输出。对于固定的 $\theta$，$f_\theta(Z)$ 仍是依赖 $Z$ 的函数，因此改变或增加输入 Token，通常会改变注意力匹配、Value 聚合和后续层输出：

$$
\theta\ \text{固定},\qquad f_\theta([P;X_e])\ \text{仍可随 }P\text{ 的取值改变}.
$$

这一结论不要求 P3 正式训练 Prompt，也不在此介绍 Key–Prompt 选择；可以使用一个**标明为教学探索的额外 Token**，对比它插入前后或取不同值时的计算变化。重点是保持原图 Token 与网络权重不变，准确显示受影响的中间量。至于该 Token 如何变成可学习参数、训练信号如何返回给它，留到 P4 解释。

### 3. 本页核心视觉与表达分工

**主视觉一：由 P2 直接放大的 Transformer Encoder Block。**

在完整 Block 构图上明确 LayerNorm、MSA、残差相加、第二个 LayerNorm、MLP/FFN 和第二个残差相加的位置，不让它们成为孤立的术语卡。必须能沿连线追踪一轮完整前向的数据顺序。

**主视觉二：一个可复算的 Attention 局部计算场景。**

以少量 Token 表达目标 Query、来源 Key/Value、匹配分数、Softmax 权重与 Value 汇聚。可以用选定目标 Token 或逐步展开的交互控制观察计算，但每一阶段都必须有可解释的输入与输出。应避免巨大的密集连线矩阵遮挡文字或把普通 Transformer 内部 Query/Key 与后续 L2P 的外部检索 Query/Key 混为一谈。

**收束视觉：冻结网络、改变输入 Token 的比较。**

同一 Transformer 网络保持位置与外观不变；参数冻结有明确的视觉标识。只改变教学用附加 Token 的状态，然后对照 Attention 中间结果和输出表示。此处的变化是前向计算结果变化，并非模型训练后的权重变化。

**阅读完成后的认识**：读者可以解释一个 Encoder Block 的实际计算顺序，理解 Token 相互影响的机制，也能区分**固定参数**与**固定输出**这两个概念。

**交给 P4 的问题**：如果增加的 Token 确实能够影响冻结 ViT 的输出，是否能把这些 Token 设计成可学习参数，并通过分类损失训练它们，从而在不更新主干权重的情况下适应新任务？

## 五、三页的视觉连续性与概念边界

### 1. 稳定身份与镜头层级

前三页应使用可追踪的视觉系统，而不是三个独立重新绘制的网络。

| 对象 | P1 | P2 | P3 |
| --- | --- | --- | --- |
| 示例图像 | 连续学习中的训练图或旧类别测试图 | 同一图像被切成 Patch | 从同一图像取得局部 Token 示例 |
| 主体网络 | 先当作可训练分类黑盒 | 展开成 `f_e → f_r → 读出` | 放大 `f_r` 中的一个 Block |
| 参数状态 | 展示顺序训练带来的变化风险 | 交代预训练主干与分类头的区别 | 冻结 Block 权重，观察输入变化的影响 |
| Token | 尚不引入完整术语 | 建立 Patch Token、`[CLS]`、位置与维度 | 解释 Q/K/V、Attention、FFN 的计算 |
| 主画面尺度 | 任务时间线与整体网络 | 端到端架构及堆叠层级 | Block 剖面、Attention 局部计算 |

布局上，P1 侧重横向时间与任务切换；P2 侧重高质量整体系统架构；P3 侧重从完整 Block 缩放到一次 Attention 计算，再返回多层 Encoder。三页不必套用相同的双栏、矩形卡片和交互样式，但字体、颜色语义、图形工艺、箭头类型与主要对象的外观应一致。

### 2. 必须明确的技术边界

- **P1**：训练时可以知道任务划分，测试时无任务 ID 的 class-incremental 条件与训练时也无任务边界的 task-agnostic 条件不能混同。基础 L2P 不要求旧数据回放，但并未证明所有数据分布下绝不遗忘。
- **P2**：普通 ViT `[CLS]` 分类读出只用于建立基础模型认识，不能提前冒充 L2P 的最终分类读出。L2P 论文 §4.3 规定其带 Prompt 的分类表示取 Prompt 输出位置的平均值。
- **P3**：Transformer 内部 Q/K/V 与 L2P 后续 Prompt Pool 的外部 Query、Key 是两套不同机制。参数冻结时 Attention 等计算继续执行；只有预训练权重保持不变。
- **整段**：教学中出现的模拟权重、预测分数、Token 小例子应由明确规则计算并标注示例属性，不声称是论文实验的真实模型轨迹。

### 3. 后续内容保留位置

这三页只建立 P4 所需的认知基础。下面这些内容不在 P1–P3 首次完整教学：Prompt Tuning 的优化过程、Prompt Pool 的容量与索引、外部 Key–Prompt 配对、冻结 ViT 生成 Query 的检索支路、余弦 Top-N、Key 匹配损失、联合训练、多任务参数继承与最终 L2P 算法贯通。它们需要在后续页面按问题出现的时机逐步引入。

## 六、P1–P3 的内容验收条件

完成设计时，不以“页面存在”或“能播放动画”为准，至少需要读者能够回答下列问题：

1. **P1**：新任务的数据到来后，为什么继续训练同一模型可能影响旧类别？为什么测试时的任务 ID 是重要约束？
2. **P2**：一张 $224\times224$ 图像如何得到 196 个 Patch Token 与一个 `[CLS]` Token？`f_e`、Encoder 堆叠 `f_r` 和最后读出各在哪里？
3. **P3**：某个 Token 如何通过 Q/K 匹配和 Value 加权得到新表示？Multi-Head、LayerNorm、残差和 FFN 在一层 Block 中怎样衔接？
4. **整体交接**：为什么“冻结网络参数”并不等于“输入变化时网络输出不能改变”？为什么这个事实使 P4 的可学习 Prompt Token 变得可行？

如果能从 P1 的同一个网络，进入 P2 的完整 ViT，再定位 P3 的 Block 并解释其中的计算，最后自然提出 P4 的问题，这三页的认知主线才算闭合。
