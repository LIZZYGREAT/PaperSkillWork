# L2P：P4–P6 教学主线与内容规划

> 对应论文：Wang et al., *Learning to Prompt for Continual Learning*（arXiv:2112.08654v2）。  
> 参考资料：《L2P论文笔记》《L2P前置知识笔记》及原论文第 3.2、4.1–4.3 节、Figure 2、公式 (1)–(5)。  
> 文档定位：PaperSkill 教程 P4–P6 的**教学主线与内容边界**。此阶段确定讲什么、为什么按此顺序讲、页面间交接什么认识；**不预先限定页面布局、图形形式、交互或动画数量**。所述单 Prompt 系统、演示性数值和用于解释的推导，均属于教学组织，不应被写成论文独立提出的额外算法。

## 一、三页的整体教学目标与衔接

前三页已建立如下认识：P1 说明连续学习中不断获得新数据、仍需保留旧类别识别能力的任务要求；P2 从图像 Patch 和 Token 开始建立预训练 ViT 的整体架构；P3 解释 Self-Attention、Encoder Block 与多层特征变换，进而得到一个关键结论：**冻结网络权重以后，输入 Token 的变化仍可能改变注意力与最终输出表示。**

P4 从这一结论继续推导：既然输入 Token 能影响冻结模型，能否把一段 Token 设置成可学习参数，从而让模型适应新任务？完成最小 Prompt Tuning 系统后，便会发现多个任务继续修改同一 Prompt 仍可能发生干扰。P5 因此建立包含多个 Prompt 的参数池，以及不依赖任务 ID 的 Query–Key 检索，让不同输入能够选择并部分共享 Prompt。P6 接住 P5 的检索结果，将多个选中 Prompt 放回 ViT 的正式前向传播，最后得到类别预测。

```text
P3：输入 Token 可以影响冻结 Transformer 的计算结果
  ↓
P4：将一段 Token 设为可学习 Prompt，建立单 Prompt 的训练闭环
  ↓  单 Prompt 在连续任务中仍会受到共同更新
P5：引入 Prompt Pool，通过输入 Query 与 Key 匹配选择 Top-N Prompt
  ↓  已确定使用哪些 Prompt，但尚未完成正式 L2P 分类
P6：拼接多个 Prompt 与图像 Token，经冻结 Transformer、Prompt 位置池化与分类头输出结果
  ↓  已获得预测，但检索 Key 与 Prompt 如何分别学习仍待解释
P7：联合分类损失与 Key 匹配损失，完成正式 L2P 的参数更新
```

**三页职责应保持分离：**P4 解释“Prompt 为什么能学习”，P5 解释“当前样本应该使用哪些 Prompt”，P6 解释“选出的 Prompt 怎样参与完整分类”。P4 的单 Prompt 是为阐明机制而采用的简化系统；P6 才严格按 L2P 原论文的多 Prompt 输入和分类读出位置讲解，不应把两者混成同一种实验配置。

## 二、P4：Prompt Tuning——让冻结的 ViT 适应新任务

### 1. 从 P3 的结论引出可学习 Token

P3 已解释：Self-Attention 的 Q/K/V 计算取决于当前输入 Token，因此网络参数即使固定，改变输入序列仍可能影响各层 Token 的输出。这为使用少量可训练参数适应新任务提供了技术入口。

回到 P1 的连续学习需求：模型需要继续学习新数据，但希望尽可能保留预训练模型已有的表征能力。一种可尝试的方向是保持预训练特征网络不变，并在其输入中加入一段可学习的连续向量，让这段向量通过 Transformer 的计算调节预测。

这时再正式引入 **Prompt Tuning**。这里的 Prompt 是向量参数，不要求对应自然语言提示词、真实图像 Patch 或预先指定的类别语义。

### 2. 将单个 Prompt 接入冻结 ViT

沿用 P2 中的架构：预训练图像嵌入层 $f_e$ 将图像 $x$ 转换为 Token 序列 $x_e=f_e(x)\in\mathbb R^{L\times D}$，预训练 Transformer Encoder $f_r$ 对该序列进行特征处理。此处将 $f_e$ 与 $f_r$ 视为已经预训练好的冻结模块。

引入一个长度为 $L_p$、隐藏维度为 $D$ 的可训练 Prompt：

$$
P\in\mathbb R^{L_p\times D}.
$$

因为每个 Prompt Token 和每个图像 Token 的特征维度相同，可以沿 Token 序列长度拼接：

$$
x_p=[P;x_e]\in\mathbb R^{(L_p+L)\times D},\qquad H=f_r(x_p).
$$

拼接增加的是序列中的 Token 数量，没有修改每个 Token 的维度，也没有向冻结主干内部添加新的可训练 Transformer 层。

此处只需简短引用 P3：Prompt Token 同样参与 Self-Attention，既可影响图像 Token 的表示，其自身输出也可能聚合图像信息。因此冻结 $f_r$ 并不意味着 $H$ 与 Prompt 无关，不需要重新讲解 Attention 的全部公式。

### 3. 通过分类误差学习 Prompt

要让新增 Prompt 适应数据，需要形成最小训练闭环。给定样本 $(x,y)$，取扩展序列输出中的某个分类表示 $h(P,x)$，经过分类器 $g_\phi$ 生成类别分数，再计算交叉熵：

$$
\mathcal L_{\mathrm{cls}}
=\operatorname{CE}\bigl(g_\phi(h(P,x)),y\bigr).
$$

此处 $h(P,x)$ 只作为**单 Prompt 教学系统**的分类读出抽象；它的具体位置无需提前规定为正式 L2P 的读出方式。原论文 L2P 使用多个 Prompt 的输出位置平均池化，留待 P6 说明。

由于损失经由 Transformer 输出依赖于 Prompt，即使主干权重被冻结，对 Prompt 的梯度仍可非零：

$$
\nabla_P\mathcal L_{\mathrm{cls}}\neq 0\qquad\text{（一般情形）}.
$$

反向传播会经过冻结 Transformer 的计算操作，将梯度传回可学习的输入 Prompt；冻结指不更新 $f_e,f_r$ 的参数，而非切断其输入上的梯度。分类器 $g_\phi$ 也可训练。

本段至少需要完整说明一次操作：**初始 Prompt → 与图像 Token 拼接 → 冻结 ViT 前向 → 分类误差 → 对 Prompt 求梯度 → 更新 Prompt 的值**。无需在这里讲解 Adam 的内部状态，也不应将冻结主干表述成“不能参与反向传播”。

### 4. 把单 Prompt 放回连续学习情境

在任务 A 上完成训练后，Prompt 变为 $P^{(A)}$。接下来任务 B 到来，如果继续用同一个 Prompt 进行训练，那么任务 B 的梯度仍会修改 $P^{(A)}$，可能改变旧样本原本依赖的预测行为。共享分类器也可能受到后续任务影响。

因此，**冻结 ViT 主干不等于解决了所有遗忘问题**；单个可训练 Prompt 仍然可能成为新旧任务争用的参数位置。这里无需提前断言具体的遗忘幅度，论文关于单 Prompt 的消融证据在后续实验页展开。

**本页交付给 P5 的问题：**

> 如果所有任务继续更新同一个 Prompt 仍可能相互干扰，能否准备多个 Prompt，让不同样本根据自身需求使用其中的一部分？

### 5. P4 的内容边界

P4 应讲清单个 Prompt 的参数身份、输入位置、对冻结 ViT 的影响以及训练更新路径；不提前展开 Prompt Pool 的 Key、Top-N 检索、Key 匹配损失与正式 L2P 的 Prompt 位置 AvgPool。后者分别属于 P5、P7 与 P6。ViT/Attention 的详细内部推导已由 P2–P3 负责，本页只回收用得上的结论。

## 三、P5：Prompt Pool 与输入驱动的动态检索

### 1. 从单 Prompt 的局限到多 Prompt 的组织问题

读者已经知道 Prompt 可以学习，而一个持续共享的 Prompt 可能被不同任务反复修改。自然的扩展是维护多个独立的可学习 Prompt。L2P 定义：

$$
\mathcal P=\{P_1,P_2,\ldots,P_M\},\qquad
P_j\in\mathbb R^{L_p\times D}.
\tag{1}
$$

其中 $M$ 是池中可供检索的 Prompt 个数。引入多个 Prompt 以后，系统还需要决定当前图像应当调用哪些 Prompt。

若简单地将 $P_t$ 固定分配给任务 $t$，测试时便需要知道当前图像所属任务，与 P1 提出的未知任务 ID 条件相冲突。L2P 因此让**当前样本的图像内容**决定要调用的 Prompt，不要求把 Prompt 预先永久分给某个任务。

### 2. 引入 Key–Prompt 配对记忆

为了让多个 Prompt 可检索，L2P 为每个 Prompt 配置一个可训练的 Key：

$$
\mathcal M
=\{(k_1,P_1),(k_2,P_2),\ldots,(k_M,P_M)\},
\qquad k_j\in\mathbb R^{D_k}.
$$

Key 是与输入特征比较的检索向量；Prompt 是实际送入 ViT 的可学习 Token 序列。它们形状、职责不同，只通过同一索引 $j$ 保持对应。**Key 负责选中哪个 Prompt，Prompt 负责改变选中后模型的条件输入。**

该结构是一套可持续更新的参数记忆，不应绘制或解释成保存旧图像样本的回放缓存。此时只介绍 Key 的职责与其可学习身份；它的训练信号如何产生，将由 P7 解释。

### 3. 由当前输入生成 Query

要对 Key 进行匹配，首先将当前图像 $x$ 变成同维度的查询特征。论文使用冻结的预训练 ViT，**在不插入任何新增 Prompt 的情况下**得到 `[CLS]` 特征：

$$
q(x)=f(x)[0,:],\qquad f=f_r\circ f_e,
\qquad q(x)\in\mathbb R^{D_k}.
$$

在论文的具体 ViT 实现中，这个特征维度与 Key 匹配。Query 的生成规则不随连续学习更新，因此 Key 面对的是相对固定的特征提取空间。Query 依赖图像内容，不读取显式任务 ID，也不需要额外先训练一个任务预测器。

必须在首次出现时明确消歧：**外部检索的 Query/Key 与 P3 介绍的 Transformer Self-Attention 中 Q/K/V 不是同一套变量或参数。** 前者发生在“选择 Prompt”环节，后者在 Transformer 内部用于 Token 间信息交互。

### 4. 计算距离并选取 Top-N Prompt

论文采用余弦距离作为匹配函数。一种常用形式是：

$$
\gamma(q,k_j)
=1-\frac{q^\top k_j}{\lVert q\rVert_2\lVert k_j\rVert_2}.
$$

给定输入 $x$，先计算其 Query 与全部 $M$ 个 Key 的距离，再选出距离最小的 $N$ 个不同索引。用 $S(x)$ 表示索引集合，原论文公式 (3) 的等价索引写法是：

$$
S(x)=
\underset{\substack{S\subseteq\{1,\ldots,M\}\\ |S|=N}}{\arg\min}
\sum_{j\in S}\gamma\bigl(q(x),k_j\bigr).
\tag{3}
$$

由于各个候选项的距离独立相加，这个过程可以实现为逐一计算 $M$ 个距离后选择最小的 $N$ 项，不需要枚举全部组合。随后按索引提取对应 Prompt：

$$
S(x)=\{s_1,\ldots,s_N\}
\quad\Longrightarrow\quad
\{P_{s_1},\ldots,P_{s_N}\}.
$$

例如选择结果为 $\{2,4,7\}$，就获得 $P_2,P_4,P_7$。选择索引是一轮前向计算的临时结果；Key 与 Prompt 池仍然保留，下一张样本可选出另一组索引。

### 5. 为什么选择多个 Prompt：部分共享与隔离

为解释样本级选择，可以使用一个明确标记为**补充教学示例**的情形：

$$
S(x_A)=\{1,3,4\},\qquad S(x_B)=\{3,4,5\}.
$$

两个样本同时使用 $P_3,P_4$，也各自使用不同的 Prompt。这意味着共享并非“所有任务共同更新一套完全相同的参数”，隔离也并非“每个任务永久独占一组 Prompt”。L2P 在样本级产生可重叠的参数选择集合。

如果两个样本在训练中共同选中了某个 Prompt，它可能收到两个样本的分类梯度；如果某个 Prompt 未被某样本选中，该样本的分类损失不会经该 Prompt 产生直接梯度。共享允许知识复用，也可能产生冲突，所以不能把“选中相同 Prompt”描述成共享必然有益，更不能宣称每个 Prompt 固定代表一个类别或任务。

本页完成后，读者应能沿以下顺序独立说明一次检索：

```text
输入图像 x
  → 无 Prompt 的冻结 ViT 提取 q(x)
  → q(x) 与 M 个 Key 逐一计算距离
  → 得到 Top-N 索引 S(x)
  → 根据相同索引取出对应 N 个 Prompt
```

### 6. P5 的内容边界

P5 集中讲清池结构、Query、Key–Prompt 对应关系、Top-N 和样本间的部分共享。不提前引入 Key 匹配损失的梯度更新，也不讲完整分类读出。论文公式 (4) 的**可选多样化检索**依赖训练时已知任务边界及历史选择频率，暂不放入这一核心检索教学链；待读者理解完整训练和跨任务共享后，再结合实验讨论其动机与条件。基础检索严格对应公式 (3)。

## 四、P6：选中的 Prompt 如何参与完整分类

### 1. 明确从 P5 接收的计算结果

P5 已针对输入图像 $x$ 算出 Query、选中索引 $S(x)=\{s_1,\ldots,s_N\}$，并取得对应 Prompt $P_{s_1},\ldots,P_{s_N}$。但“取得 Prompt”还不是“完成预测”。P6 负责将这些检索结果接入 L2P 正式的分类路径，还原原论文 Figure 2、公式 (2) 与第 4.3 节规定的输出读出规则。

### 2. 将多个 Prompt 与图像 Token 合并

冻结的图像嵌入层生成：

$$
x_e=f_e(x)\in\mathbb R^{L\times D}.
$$

每个选中 Prompt 包含 $L_p$ 个 Token，$N$ 个 Prompt 共有 $NL_p$ 个 Token。按照论文公式 (2)，把它们按选中索引顺序排列，随后接上图像 Token：

$$
x_p=[P_{s_1};P_{s_2};\ldots;P_{s_N};x_e]
\in\mathbb R^{(NL_p+L)\times D}.
\tag{2}
$$

这里是沿**序列长度维度拼接**，没有将 Key 拼入 Transformer，没有对 Prompt 做逐元素相加，也没有把多个 Prompt 交给不同的 ViT 子网络。总长度从 $L$ 变为 $L+NL_p$，隐藏维度 $D$ 不变。

### 3. 扩展序列经过冻结 Transformer

执行：

$$
H=f_r(x_p)\in\mathbb R^{(NL_p+L)\times D}.
$$

此时直接回收 P3：经过多层 Self-Attention，Prompt 位置与图像位置可以交换信息，因而最终的 Prompt 位置输出不仅与可学习 Prompt 有关，也与当前图像的 Token 有关。完整 ViT 主干保持冻结，但由于输入的 Prompt 不同，输出的特征仍可能不同。

这里不需要再次从头解释 Q/K/V、FFN、残差与 LayerNorm；重点是让读者明确输入扩展后，**输出仍保有每个 Token 的位置，且后续分类将读取特定位置**。

### 4. 分类读取 Prompt 位置的输出，而非原图 CLS

原论文第 4.3 节明确：L2P 的分类表示来自扩展序列中**前 $NL_p$ 个 Prompt 位置的 Transformer 输出的平均池化**：

$$
h(x)=\operatorname{AvgPool}\bigl(H[0:NL_p,:]\bigr)
=\frac{1}{NL_p}\sum_{r=1}^{NL_p}H_{r,:}
\in\mathbb R^D.
$$

在解释这个读出设计前，必须恢复两条路径的区别：

- **检索路径：**不带 Prompt 的冻结预训练 ViT，取 `[CLS]` 特征作为 $q(x)$，用于匹配 Key。
- **分类路径：**将选中的 Prompt 加入图像 Token，经过冻结 Transformer 后，取 Prompt 位置的输出均值 $h(x)$ 用于分类。

二者都依赖冻结主干，但输入序列及读出位置不同。不能把正式 L2P 的分类读出改写成“直接取原始 `[CLS]` 最终特征”，也不能对全部扩展 Token 不加区分地求均值。

### 5. 共享分类器输出类别预测

平均池化结果送入可训练的共享分类器 $g_\phi$：

$$
z=g_\phi(h(x)),\qquad
\hat y=\arg\max_c z_c.
$$

其中 $z$ 是类别 Logits；需要概率时可对 Logits 执行 Softmax。不同输入可选中不同 Prompt 组合，但仍通过同一冻结特征网络与共享分类器完成分类。至此形成一次 L2P 的正式前向链：

```text
图像 x
  ├─ 检索路径：冻结 ViT → q(x) → 与 Key 匹配 → Top-N 索引 S(x) → N 个 Prompt
  └─ 编码路径：冻结输入嵌入 f_e → 图像 Token x_e
                              ↓
               [P_s1; ...; P_sN; x_e]
                              ↓
                    冻结 Transformer f_r
                              ↓
                Prompt 位置输出 H[0:NL_p,:]
                              ↓
                         AvgPool
                              ↓
                      共享分类器 g_φ
                              ↓
                         Logits z
```

### 6. 使用原论文实验配置验证张量维度

以原论文在 Split CIFAR-100 等设置中使用的 ViT-B/16 和 $M=10,N=5,L_p=5$ 为例：一张 $224\times224\times3$ 图像切分成 $196$ 个 Patch，连同 `[CLS]` 得到 $L=197$ 个图像 Token；ViT-B/16 的隐藏维度为 $D=768$。

| 计算对象 | 形状或数量 | 在当前流程中的意义 |
| --- | --- | --- |
| 输入图像 $x$ | $224\times224\times3$ | 当前图像 |
| 图像 Token $x_e$ | $197\times768$ | 196 个 Patch + 1 个 `[CLS]` |
| Prompt Pool | $M=10$ 个 Prompt | 全部可选参数单元 |
| 单个 Prompt $P_j$ | $5\times768$ | 一个 Prompt 包含 5 个 Token |
| 当前选中 Prompt | $5\times5\times768$ | 5 个 Prompt，共 25 个 Token |
| 拼接输入 $x_p$ | $222\times768$ | 25 个 Prompt Token + 197 个图像 Token |
| Transformer 输出 $H$ | $222\times768$ | 对扩展序列的特征处理结果 |
| Prompt 位置输出 | $25\times768$ | 前 25 个 Token 的输出 |
| AvgPool 输出 $h(x)$ | $768$ | 定长分类特征 |
| 分类 Logits $z$ | 类别数维 | 共享分类器的输出 |

这个例子用于核对 $M$、$N$ 与 $L_p$ 的不同作用：$M$ 决定总共可选多少个 Prompt；$N$ 决定一次输入选择几个；$NL_p$ 才是本次实际额外注入的 Token 数。全部 $M$ 个 Prompt 并不会在每次前向中同时拼入 ViT。

### 7. 从已经得到的预测引出训练问题

现在 L2P 已能根据图像动态选择 Prompt 并输出 Logits，但若 Key、Prompt 和分类器刚刚初始化，系统不等于已经学到了合理的分类与检索行为。真实标签可以用于计算分类误差，并驱动选中的 Prompt 与分类器学习；同时，Key 也需要学会匹配当前图像的 Query。

问题在于：Top-N 输出离散索引，分类损失不会自动沿通常的连续梯度路径穿过这个选择步骤，形成对检索 Key 的有效学习。因此作者另外设计了 Key 匹配损失。此处只提出需要，尚不详细推导联合损失或参数更新。

**本页交付给 P7 的问题：**

> 既然模型已经能够产生预测，分类误差应如何训练被选中的 Prompt？而负责检索的 Key 又如何在离散 Top-N 选择下得到独立的学习信号？

### 8. P6 的内容边界

P6 需要完整覆盖正式 L2P 的前向数据路径、拼接形状、Prompt 位置 AvgPool 和共享分类器。P7 负责联合损失、梯度来源与批次参数更新；P8 负责从初始化和多批次训练到跨任务状态继承及推断的完整执行模型。不要在 P6 反复教授 P3 的 Attention 推导，也不要因解释方便将正式分类路径改成普通 ViT 的 CLS 分类。
