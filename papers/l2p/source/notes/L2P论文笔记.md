> **阅读依据**：原论文第 1、3、4、5、6 节、图 1–4、公式 (1)–(5)，以及附录 C、D 中的数据集说明和 Algorithm 1。  
> **笔记定位**：这是一份**方法与实验的正式论文笔记**。ViT、Self-Attention、Prompt Tuning、余弦距离与梯度传播的通用原理已在《L2P 前置知识笔记》中解释，这里只在理解论文新机制所必需的位置回顾。下文凡标明“补充示例 / 补充伪代码 / 推论”的内容，均用于辅助理解，不冒充论文原文。

## 一、研究问题与 L2P 的核心思路

### 1. 任务设定：顺序学习，但需要对旧任务继续预测

在连续学习中，模型依次接收任务数据

$$
\mathcal D=\{\mathcal D_1,\mathcal D_2,\ldots,\mathcal D_T\},\qquad
\mathcal D_t=\{(x_i^t,y_i^t)\}_{i=1}^{n_t}.
$$

在训练任务 $t$ 时，模型只能保证获得当前阶段的训练样本 $\mathcal D_t$；旧任务样本不一定允许保存或重新访问。但在测试时，输入 $x$ 可能来自任意已学任务，模型仍需要预测对应类别。论文尤其关注**测试时不知道任务 ID**的类别增量与领域增量学习，并进一步讨论训练时也没有明确任务边界的 task-agnostic 设置（第 3.1 节）。

传统连续学习方法往往在共享神经网络参数上解决冲突：例如限制重要参数变化、利用旧样本重放，或者为不同任务引入额外网络组件。这些方法各有代价：重放需要旧样本缓存；显式任务模块往往依赖测试时的任务身份；直接更新主干参数可能损害原先学到的表征。

L2P 提出的问题并不是“如何保证所有参数不改变”，而是：**在已有高质量预训练模型的条件下，能否把后续任务的适应过程转移到一套小规模、可按输入动态检索的参数记忆中？**

### 2. 普通 Prompt Tuning 的局限

Prompt Tuning 将可训练的 Prompt Token 拼接到预训练模型的输入序列前面，通过这些 Token 调整模型的计算，而不改动预训练主干。把这一技术直接搬到连续学习，有两个直观方案，但都存在问题。

第一种是**每个任务训练一个独立 Prompt**。不同任务的参数不相互覆盖，但测试时必须先知道该选哪个任务的 Prompt；这无法直接满足类别增量场景下未知任务身份的要求。第二种是**所有任务共享单个 Prompt**。虽然不必选择任务，但新旧任务持续更新同一组 Prompt 参数，干扰与遗忘依然可能发生。论文第 5.4 节也通过消融实验验证了单 Prompt 的明显性能下降。

因此，L2P 采用介于两者之间的设计：

- 不把 Prompt 永久绑定给任务 ID，而是放入可共享的 **Prompt Pool**。
- 不让所有输入始终使用同一个 Prompt，而是为每个样本**检索一组相关 Prompt**。
- 不从头训练或不断修改预训练 ViT，而是保持**预训练主干冻结**，学习 Prompt、检索用的 Key 和最终分类器。

这里的“知识共享”与“知识隔离”并不是两个额外显式损失，而主要通过**不同输入是否选中相同的 Prompt**来体现。相似样本可能复用部分 Prompt，差异大的样本可能使用不同组合；这种机制旨在减少无关任务争用同一小组参数。

### 3. 先建立完整运行图景

将论文图 2 与附录 Algorithm 1 合起来，L2P 对一张图像的处理流程是：

```text
当前输入图像 x
    │
    ├──────── 路径 A：检索 ─────────────────────────┐
    │   冻结的预训练 ViT 提取 q(x)                   │
    │       → 与 M 个可学习 Key 比较距离              │
    │       → 选中 Top-N Key 的索引 S(x)              │
    │       → 按索引取得 N 个 Prompt                  │
    │                                                ▼
    └──────── 路径 B：输入编码 ───────────────→ 拼接 Token
        冻结的 Patch / Token Embedding         [选中 Prompt; 图像 Token]
                                                     │
                                        冻结 Transformer Encoder
                                                     │
                                   取 Prompt 位置的输出并 AvgPool
                                                     │
                                             可训练分类器 g_φ
                                                     │
                                                 类别预测
                                                     │
                   训练时：分类损失 + Key 匹配损失 → 参数更新
                   推断时：直接输出预测，不计算损失、不更新参数
```

注意，图中的路径 A 和路径 B 都以同一张图像为输入，**路径 A 负责决定取哪些 Prompt，路径 B 负责生成原始图像 Token**；二者在拼接环节汇合。路径 A 所使用的查询特征，是在**尚未插入 Prompt**的条件下由冻结模型提取的，并不是分类路径最后得到的特征。

## 二、模型初始化：主干、Prompt Pool、Key 与分类器

### 1. 冻结的预训练 ViT 提供什么能力

论文采用预训练的 Vision Transformer（实验中使用 ViT-B/16）作为主干。沿用原论文符号，把它划分为输入嵌入层 $f_e$ 和 Transformer Encoder $f_r$，令 $f=f_r\circ f_e$ 表示不包含最终分类头的预训练特征模型。

对于图像 $x\in\mathbb R^{H\times W\times C}$，嵌入层输出

$$
x_e=f_e(x)\in\mathbb R^{L\times D},
$$

其中 $L$ 为输入 Token 序列长度，$D$ 为每个 Token 的隐藏维度。按照论文第 3.2 节的记法，序列包含用于表征整张图像的 `[class]` Token。此时 $f_e$ 和 $f_r$ 已有预训练参数，**连续学习全程不更新它们**。

预训练主干的作用有两层：一是产生用于检索的、相对稳定的视觉 Query 特征；二是作为处理“图像 Token + Prompt Token”的固定计算网络。冻结主干并不等于整套模型不学习，真正承担后续训练的是新增的少量参数。

### 2. Prompt Pool：可供组合的参数记忆

原论文公式 (1) 定义

$$
\mathcal P=\{P_1,P_2,\ldots,P_M\},\qquad
P_j\in\mathbb R^{L_p\times D}.
\tag{1}
$$

$M$ 是 Prompt Pool 的容量，$L_p$ 是**单个 Prompt 包含的 Token 数**，$D$ 与预训练模型的 Token 嵌入维度一致。一个 $P_j$ 并不是单个标量或一个类别标签，而是一段可学习的连续向量序列。它可以在训练中改变数值，随后被不同输入反复检索并共同使用。

如果只保留 $\mathcal P$ 而不增加检索机制，系统仍不知道当前输入应该选择哪些 Prompt。因此，论文又为每一个 Prompt 配置一个可学习的检索 Key。

### 3. Key–Prompt 配对记忆

Prompt Pool 进一步组织为 $M$ 个一一对应的参数对：

$$
\mathcal M=\{(k_1,P_1),(k_2,P_2),\ldots,(k_M,P_M)\},
\qquad k_j\in\mathbb R^{D_k}.
$$

Key 集合记作 $\mathcal K=\{k_j\}_{j=1}^{M}$。这里必须区分两个概念：

| 部件 | 存储什么 | 参与哪个过程 | 学习目标 |
|---|---|---|---|
| Key $k_j$ | 一个 $D_k$ 维检索向量 | 与 Query 比较，决定哪些 Prompt 被选中 | 接近选中它的样本 Query |
| Prompt $P_j$ | 一段 $L_p\times D$ 的 Token 向量 | 被拼接到模型输入，经 Transformer 影响分类表示 | 让选中它的样本分类得更好 |

**Key 负责“找到谁”，Prompt 负责“如何影响预测”。** 两者共享索引，但不能把 Key 误当成输入 Transformer 的 Prompt Token。Key 的存在使检索所依据的表示与分类所用的表示可以分别学习；论文通过取消可学习 Key 的消融实验检验了这种分离设计（第 5.4 节）。

### 4. 分类头及初始化状态

分类器记为 $g_\phi$，$\phi$ 是其可训练参数。它接收经过 Transformer 和池化后的向量，并输出分类结果。论文采用**同一个分类器**处理顺序出现的任务，而不是为每个任务在测试时另行选择分类头。

在正式训练开始前，系统拥有以下状态：冻结的 $f_e,f_r$、初始化的 Prompt 参数 $\mathcal P$、Key 参数 $\mathcal K$、分类器参数 $\phi$；如果启用后文的可选多样化检索策略，还会有 Prompt 历史选择频率表。此时尚未训练出“任务 1 的专属 Prompt”之类的显式映射。

## 三、输入驱动的 Prompt 检索：从 Query 到 Top-$N$

### 1. 首先为图像计算不依赖任务身份的 Query

设某次训练从当前任务取到样本 $(x,y)$。在选 Prompt 之前，先利用原始图像计算检索向量：

$$
q(x)=f(x)[0,:]\in\mathbb R^{D_k}.
$$

论文第 4.2 节选用**冻结的预训练模型在 `[class]` 位置输出的特征**作为 Query，令其维度与 Key 匹配。这里的 $f(x)$ 是未加入新 Prompt 的预训练特征计算，$[0,:]$ 取其第一个 Token 位置的隐藏向量。论文强调 Query 函数不应具有在连续学习中更新的参数，并应保持与任务无关；这保证检索特征空间不会随着当前任务的梯度训练而整体漂移。

因此，同一个输入的检索流程不需要先判断任务编号，也不需要额外训练一个任务分类器。它只依赖图像内容、固定的特征提取器，以及当前 Prompt Pool 的 Key。

### 2. 使用 Key 匹配选择 Prompt 子集

设 $\gamma(q,k)$ 为 Query 与 Key 之间的距离函数，论文实际采用余弦距离。在常见定义下，

$$
\gamma(q,k)=1-\frac{q^\top k}{\|q\|_2\|k\|_2}.
$$

距离越小，两个向量的方向越接近。对输入 $x$，L2P 在所有 $M$ 个 Key 中选出距离最小的 $N$ 个不同索引，记选中的索引集合为 $S(x)=\{s_1,\ldots,s_N\}$。论文公式 (3) 写成

$$
\mathcal K_x=
\underset{\{s_i\}_{i=1}^{N}\subseteq[1,M]}{\arg\min}
\sum_{i=1}^{N}\gamma\bigl(q(x),k_{s_i}\bigr).
\tag{3}
$$

这里论文用 $\mathcal K_x$ 表示选中的 Key 子集；实现时通常需要同时保留对应的索引 $S(x)$，以便取回一一配对的 Prompt。由于各个候选 Key 的距离分数是独立计算的，且没有额外组合约束，这个优化等价于**计算 $M$ 个距离，然后取最小的 $N$ 项**；不需要枚举所有 $\binom{M}{N}$ 个组合。

如果样本 $x$ 的 Top-$N$ 索引为 $\{2,4,7\}$，则本次使用 $P_2,P_4,P_7$。下一个样本即使属于同一个训练任务，也可能选中不同组合。因此，论文称其为 *instance-wise*（样本级）选择，而非 task-wise（任务级）分配。

### 3. 检索结果为何能同时产生共享与隔离

一个 Prompt 是否被两个样本共享，取决于二者的 Query 与当前 Key 空间的匹配结果。如果两张图像选中相同索引，训练时它们会共同优化这些 Prompt；如果索引不重合，它们的 Prompt 更新在这部分参数上便不会相互干扰。

下面是**补充示例（非论文给定数据）**：假设 $M=6,N=2$。在某一训练时刻，来自任务 A 的两张图像分别选择 $\{P_1,P_3\}$ 与 $\{P_1,P_4\}$；随后任务 B 的图像选择 $\{P_3,P_5\}$。那么 $P_3$ 在两个任务之间被复用，$P_1$ 只受到上述任务 A 样本的更新，$P_5$ 只受到上述任务 B 样本的更新。注意，这些只是当下的选择结果，并不意味着之后的任务永远不能选择 $P_1$ 或 $P_5$。

由此可见，Prompt Pool 提供的是**软性的、数据驱动的参数复用机制**，而不是永久分区。共享有利于迁移，也可能引入冲突；分开使用有利于隔离，但若分得过多则可能减少知识迁移。这也是论文必须通过消融与 Prompt 使用频率分析验证设计的原因。

### 4. 可选的多样化选择：利用已知训练任务边界

基础 L2P 完全可以使用公式 (3) 做检索，不依赖已知任务边界。但在任务差异很大的连续学习场景，多个任务可能频繁争用少数 Prompt。论文第 4.2 节为**训练时能够获知任务边界**的情况提供一个可选策略。

在训练第 $t$ 个任务时，维护频率表

$$
H_t=[h_1,h_2,\ldots,h_M],
$$

其中 $h_j$ 是在此前任务（直到 $t-1$）中 $P_j$ 被选中的归一化频率。用这个历史频率对距离加权，公式 (4) 为

$$
\mathcal K_x=
\underset{\{s_i\}_{i=1}^{N}\subseteq[1,M]}{\arg\min}
\sum_{i=1}^{N}\gamma\bigl(q(x),k_{s_i}\bigr)\,h_{s_i}.
\tag{4}
$$

论文将该项解释为对历史高频 Prompt 的惩罚，以鼓励新阶段选择更为多样的 Prompt。它利用的是**训练阶段的历史选择统计与已知任务边界**，而不是让测试阶段读取任务 ID。论文明确规定：**仅在训练期间可选用公式 (4)；推断统一使用公式 (3)**。

这部分不可误写为基础 L2P 的必要组成，也不应在没有任务边界的 task-agnostic 设置中强行引入。原文没有在公式层面完整指定初始频率和零频率的工程处理细节；若以代码严格复现，应核对相应实现，而不能从公式自行补写为论文既定规则。

### 5. 检索模块伪代码

以下为**根据论文公式 (3)、(4) 补充的模块伪代码**；计算顺序与论文一致：

```text
FUNCTION SelectPrompts(x, frozen_f, K, P, N, use_diversity, H_t):
    # 不带 Prompt 的冻结模型提取 Query
    q ← frozen_f(x)[CLS_position]

    FOR j = 1 ... M:
        d[j] ← cosine_distance(q, K[j])
        IF use_diversity:
            d[j] ← d[j] * H_t[j]  # 只在满足前提的训练阶段启用

    S ← indices_of_N_smallest(d)
    selected_keys    ← K[S]
    selected_prompts ← P[S]
    RETURN q, S, selected_keys, selected_prompts
```

伪代码中的 `K[S]` 与 `P[S]` 保持**同一索引顺序**，这是 Key–Prompt 一一配对的直接要求。

## 四、条件化前向传播：选中的 Prompt 如何形成预测

### 1. 图像嵌入和 Prompt 序列的汇合

确定选择索引 $S(x)=\{s_1,\ldots,s_N\}$ 后，图像从嵌入层得到 $x_e=f_e(x)\in\mathbb R^{L\times D}$。将 $N$ 个 Prompt 按 Token 维度依次放到原始图像 Token 之前，原论文公式 (2) 为

$$
x_p=[P_{s_1};P_{s_2};\ldots;P_{s_N};x_e]
\in\mathbb R^{(NL_p+L)\times D}.
\tag{2}
$$

这里的分号表示**沿序列长度维度拼接**，而不是逐元素相加、平均 Prompt、替换图像 Patch，也不是修改 Transformer 中的权重矩阵。新的序列长度由 $L$ 变为 $L+NL_p$，Token 隐藏维度保持 $D$。

因此，对当前输入而言，检索模块先决定加入**哪些 Prompt**；前向传播模块再决定这些 Prompt 如何通过冻结 Transformer 参与特征交互。顺序不能倒置，因为完整分类输入 $x_p$ 依赖于此前的选择结果。

### 2. 冻结 Transformer 仍能受到 Prompt 影响

令 Transformer Encoder 对扩展序列进行计算：

$$
Z=f_r(x_p)\in\mathbb R^{(NL_p+L)\times D}.
$$

冻结是指 $f_r$ 自身参数不更新，并不意味着固定输入到输出的映射只会给出一个不随 Prompt 改变的结果。Self-Attention 的输入包含新插入的 Prompt Token，它们可以与图像 Token 进行注意力交互。因此，即使 $f_r$ 权重固定，改变 $P_{s_i}$ 仍会改变输出 $Z$。

这一点对 L2P 尤其重要：它不是在旧模型之外维护一个完全独立的分类器，而是通过可训练 Token **条件化调用预训练模型已有的表征能力**。

### 3. 分类究竟读取哪些输出 Token

论文第 4.3 节对输出池化位置给出明确规定。对扩展输入 $x_p$，取**前 $NL_p$ 个位置，也就是新加入的 Prompt Token 所对应的 Transformer 输出**，执行平均池化：

$$
h(x)=f_r^{\mathrm{avg}}(x_p)
=\operatorname{AvgPool}\bigl(f_r(x_p)[0:NL_p,:]\bigr)
\in\mathbb R^D.
$$

随后由一个分类器产生类别 Logits，再通过 Softmax 得到类别概率：

$$
z=g_\phi(h(x)),\qquad
p(y=c\mid x)=\frac{\exp(z_c)}{\sum_{r}\exp(z_r)}.
$$

这是一个重要的、容易与普通 ViT 混淆的细节：**原论文 L2P 的分类表示来自 Prompt 位置输出的平均池化，而不是直接取原始 `[class]` Token 的最后一层输出**。不过 `[class]` 仍然用于前面不带 Prompt 的 Query 提取。两者出现在同一个算法的不同路径，作用不能混为一谈。

### 4. 一次前向计算的维度实例

以论文在 Split CIFAR-100 上使用的 ViT-B/16 配置为例：输入图像调整为 $224\times224$；预训练模型 Token 维度取 $D=768$；Patch 数为 $196$，再计入 `[class]`，则图像序列长度通常为 $L=197$。论文设置 $M=10$、$N=5$、$L_p=5$。

于是每个样本从 Prompt Pool 选择 $5$ 个 Prompt，共形成 $5\times5=25$ 个 Prompt Token；分类路径的总序列长度为 $197+25=222$。Transformer 输出可以看作 $222\times768$ 的 Token 表示，其中**前 25 个 Prompt 位置**被取出平均为一个 $768$ 维向量，再输入分类器。

这个例子说明三个超参数的分工：$M$ 控制可用记忆单元数，$L_p$ 控制单个 Prompt 的容量，$N$ 控制**每次实际调用**多少个 Prompt。一次前向只使用 $N$ 个，不代表其余 $M-N$ 个已经从系统中删除。

## 五、训练目标与参数更新：从预测误差写回记忆

### 1. 为什么分类正确还不足以学会检索

到此为止，当前样本已经经历了 Query 提取、Top-$N$ 检索、Prompt 拼接、Transformer 计算和分类。训练的下一步，是将预测误差转化为对可训练参数的更新。

分类损失可以优化**已经被选择**的 Prompt，使它们更适合当前样本；但 Top-$N$ 本身返回的是离散索引。如果只依靠分类损失，不能自然地将连续梯度穿过“某个 Key 的排名有没有进入前 $N$ 名”这一离散选择，从而稳定学习到合理的 Key 表示。

因此论文引入一个独立的**Key 匹配损失**：在完成检索后，把当前已选 Key 朝该样本的冻结 Query 靠近，让后续相似的 Query 更容易找到相关记忆。

### 2. 联合损失函数

论文公式 (5) 把分类损失与匹配损失相加：

$$
\min_{\mathcal P,\mathcal K,\phi}
\underbrace{\mathcal L\bigl(g_\phi(f_r^{\mathrm{avg}}(x_p)),y\bigr)}_{\mathcal L_{\mathrm{cls}}}
+
\lambda\underbrace{\sum_{k_{s_i}\in\mathcal K_x}
\gamma\bigl(q(x),k_{s_i}\bigr)}_{\mathcal L_{\mathrm{match}}},
\quad \mathcal K_x\text{ 由公式 (3) 选出}.
\tag{5}
$$

其中 $\mathcal L$ 是 Softmax 交叉熵，$\lambda$ 调节 Key 匹配损失所占权重。式 (5) 中的三个优化对象恰好对应系统新增的三类可训练状态：Prompt Pool $\mathcal P$、Key 集合 $\mathcal K$、分类器 $\phi$。预训练的 $f_e,f_r$ 不在待优化参数集合内。

按一次检索已经确定的索引观察训练信号：

- **选中的 Prompt**：通过 $x_p\to f_r\to h\to g_\phi\to\mathcal L_{\mathrm{cls}}$ 接收分类梯度。
- **选中的 Key**：通过 $\gamma(q(x),k_{s_i})$ 接收匹配梯度；Query 来自冻结模型，不因这一损失而更新。
- **分类器**：直接通过交叉熵接收分类梯度。
- **未选中的 Key、Prompt**：不参与此样本的损失计算，因此此样本不对它们产生对应梯度。

这里“选中的 Key”与“选中的 Prompt”不是靠同一条梯度链实现更新。Key 更新改变未来的检索匹配，Prompt 更新改变未来选中它时的分类效果；二者依靠共享索引在系统层面相互配合。

### 3. 从单个样本到 Mini-batch 的联合更新

对于一个 Mini-batch $\mathcal B$，其中不同样本各自进行独立的 Top-$N$ 选择。令样本 $i$ 的总损失为 $\ell_i$，则一个批次的训练目标可表示为

$$
\mathcal L_{\mathcal B}=\sum_{(x_i,y_i)\in\mathcal B}\ell_i,
$$

实践中也可按批大小取均值以规范梯度尺度；**论文 Algorithm 1 的表述是累积每个样本的损失**，这里不擅自将“均值”视为原论文明确给定的实现。

随后，对本批次至少被一个样本选中的参数进行优化。用普通梯度下降写出依赖关系：

$$
\begin{aligned}
k_j &\leftarrow k_j-\eta\nabla_{k_j}\mathcal L_{\mathcal B},\qquad &&j\in S_{\mathcal B},\\
P_j &\leftarrow P_j-\eta\nabla_{P_j}\mathcal L_{\mathcal B},&&j\in S_{\mathcal B},\\
\phi &\leftarrow\phi-\eta\nabla_\phi\mathcal L_{\mathcal B},&&
\end{aligned}
$$

其中 $S_{\mathcal B}$ 是本批次所有样本选中索引的并集。原论文附录 Algorithm 1 使用这种梯度步形式表达更新过程；**实验实际使用的是 Adam 优化器**，不能把伪代码中的 $\eta\nabla$ 误认为作者实验使用了纯 SGD。

如果同一 Prompt 被一个批次里的多张图片选中，它会收到来自这些样本分类损失的累积梯度，最后进行一次优化器更新；不是每处理一张图像就立即更新参数，然后才处理批次中的下一张图像。这也是为什么训练流程先计算整个批次损失，再更新参数。

### 4. 一次参数更新如何影响后续样本

假设样本 $x_a$ 选择 $P_2$，完成反向传播后，$P_2$ 被更新，因此以后任何选择 $P_2$ 的输入，其扩展 Token 序列及分类结果都可能变化。同时，对应的 $k_2$ 被匹配损失更新，因此以后任意输入的 Top-$N$ 结果也可能变化。

这意味着 L2P 的记忆同时有两个动态层次：

1. **内容变化**：$P_j$ 学到了新的分类相关信息。
2. **寻址变化**：$k_j$ 改变了哪些输入更可能使用 $P_j$。

虽然冻结 ViT 避免了对主干特征参数的持续覆盖，Prompt 与分类器仍可能受到后续任务干扰，因此它是**缓解遗忘的方法**，而不是对旧任务性能作数学上不下降的保证。

### 5. 训练单个 Mini-batch 的模块伪代码

以下为**根据公式 (2)、(3)、(5) 与附录 Algorithm 1 提炼的模块伪代码**。为突出本模块，省略了优化器状态的内部运算。

```text
FUNCTION TrainOneBatch(B, frozen_f_e, frozen_f_r, K, P, classifier, λ):
    total_loss ← 0
    selected_indices_in_batch ← ∅

    FOR (x, y) IN B:
        q, S, selected_keys, selected_prompts ← SelectPrompts(x, ..., K, P, N)
        x_e ← frozen_f_e(x)
        x_p ← Concat(selected_prompts[1], ..., selected_prompts[N], x_e)
        z_tokens ← frozen_f_r(x_p)
        h ← Mean(z_tokens[0 : N*L_p])
        logits ← classifier(h)

        L_cls ← CrossEntropy(logits, y)
        L_match ← Sum(cosine_distance(q, K[j]) FOR j IN S)
        total_loss ← total_loss + L_cls + λ * L_match
        selected_indices_in_batch ← selected_indices_in_batch ∪ S

    Backward(total_loss)
    OptimizerStep(K[selected_indices_in_batch],
                  P[selected_indices_in_batch], classifier)
    # 冻结 f_e、f_r，其他未选中的池参数没有来自本批次的梯度
    RETURN total_loss
```

## 六、跨任务训练：L2P 如何累积、选择并复用历史知识

### 1. 第一个任务：从随机记忆参数开始形成分工

在任务 1 开始前，所有 Prompt 与 Key 是待学习参数，还没有被指定任何任务含义。训练数据依次进入 Mini-batch，每张图像都用冻结主干产生 Query，在当时的 Key 集合中挑选 Top-$N$ Prompt，计算分类和匹配损失，再更新池中被使用的参数与分类器。

随着训练推进，一些 Key 可能逐渐靠近某类视觉特征，相应 Prompt 则逐渐适合被这些输入调用。这里产生的是**由数据与优化结果形成的分工**，不是预先按照“每个 Prompt 对应一种类别”或“每个 Prompt 对应一个任务”分配内存。

训练任务 1 后的持久状态主要为

$$
(\mathcal P^{(1)},\mathcal K^{(1)},\phi^{(1)}),
$$

以及可选的 Prompt 使用统计。预训练主干仍是最初冻结的 $f_e,f_r$。

### 2. 第二个及之后的任务：继承旧参数，而不是重建网络

任务 2 开始时，系统**继续使用上一阶段训练后的** $\mathcal P^{(1)},\mathcal K^{(1)},\phi^{(1)}$。新任务样本仍按完全相同的路径产生 Query、检索 Prompt、拼接输入并预测。由于当前 Key 的值已经改变，选出的 Prompt 组合反映的是此前训练累积的检索结构。

如果新任务输入与某些历史输入相似，可能继续选择旧的 Prompt，于是这些 Prompt 接收新任务梯度，实现一定程度的共享；如果差异较大，也可能选择另外一些 Prompt，使新梯度较少修改旧样本频繁使用的参数。

这一机制在所有后续任务不断重复。用状态递推概括：

$$
(\mathcal P^{(t-1)},\mathcal K^{(t-1)},\phi^{(t-1)})
\xrightarrow[\text{仅访问当前训练数据 }\mathcal D_t]{\text{检索、损失计算、优化}}
(\mathcal P^{(t)},\mathcal K^{(t)},\phi^{(t)}).
$$

**这个状态递推是对论文算法的整理，而非另一个论文公式。** 它揭示了 L2P 的历史知识承载位置：不是一份旧任务样本缓存，也不是旧模型快照，而是不断延续、按输入检索的小规模 Key–Prompt 参数以及共享分类器参数。

### 3. 原论文 Algorithm 1：整体主流程

以下伪代码以原文**附录 D 的 Algorithm 1 为依据**，保留“任务循环 → 训练轮次 → 批次样本 → 批次损失 → 参数更新”的先后关系；其中 `FOR EACH mini-batch` 是把原文 `Draw a mini-batch` 展开为通常的批次迭代写法，以呈现完整训练轮次，并非论文另行提出的新步骤。

```text
ALGORITHM L2P_Train
INPUT:
    预训练嵌入层 f_e、预训练 Transformer f_r
    任务序列 D_1, ..., D_T
    Prompt 池 P_1, ..., P_M；Key 集合 k_1, ..., k_M
    单次选择数量 N；学习率 η；匹配损失权重 λ
    每个任务的训练轮次 E_t；分类器 g_φ

INITIALIZE:
    初始化 P、K、φ
    冻结 f_e 和 f_r

FOR t = 1 ... T:
    # 如果采用已知边界的多样化策略，可使用先前任务的 H_t
    FOR epoch = 1 ... E_t:
        FOR EACH mini-batch B from D_t:
            L_B ← 0
            S_B ← ∅

            FOR (x, y) IN B:
                q ← FrozenViT(x)[CLS_position]
                S ← TopNKeys(q, K)  # 公式 (3)；可选训练期公式 (4)
                x_e ← f_e(x)
                x_p ← Concat(P[S_1], ..., P[S_N], x_e)  # 公式 (2)
                h ← AvgPool(f_r(x_p)[0 : N*L_p, :])
                L_x ← CrossEntropy(g_φ(h), y)
                       + λ * Sum(γ(q, k_j) FOR j IN S) # 公式 (5)
                L_B ← L_B + L_x
                S_B ← S_B ∪ S

            反向传播 L_B
            更新所选 k_j、P_j（j ∈ S_B）及分类器 φ
            不更新预训练参数 f_e、f_r

    # 当前任务结束后，保留 P、K、φ 供下一任务使用
    # 若采用多样化策略，维护历史 Prompt 选择频率

OUTPUT: 冻结主干、训练后的 P、K、φ
```

原论文 Algorithm 1 以集合 $\mathcal K_B,\mathcal P_B$ 记录本批次被选中的 Key 和 Prompt，再遍历更新。上面改用**相同索引集合 $S_B$**表示，是为了清楚保证 Key 与 Prompt 始终按索引正确配对；这一实现层面的表述调整不改变论文计算含义。

### 4. 什么情况下可以不使用明确任务边界

在 task-agnostic 设置中，训练流中的数据分布可能逐步改变，却不存在可以读取的“任务 1 结束、任务 2 开始”信号。基础 L2P 的单次计算只依赖当前 $(x,y)$、冻结主干、Key Pool、Prompt Pool 和分类器，不需要一个任务 ID 来选择模块，因此仍可对连续批次执行相同的训练操作。

但应当区分两层意思：**不需要任务边界来检索与预测**，并不表示所有带任务边界的训练技巧都可在这种设置中照搬。依赖历史任务频率 $H_t$ 的公式 (4) 是可选扩展，在没有明确边界时应使用基础的公式 (3)。

## 七、推断流程：如何在不知道任务 ID 时预测旧类与新类

训练结束（或者任意训练阶段）后，给定一张未知来源的测试图像 $x$，L2P 不尝试先判断“这是任务几”，也不会拿着所有旧任务数据重新训练。它直接：

1. 用冻结的、未加入 Prompt 的预训练 ViT 计算 $q(x)$。
2. 利用公式 (3) 检索当前 Key Pool 中最近的 $N$ 个 Key，获取对应 Prompt。
3. 用同一冻结嵌入层生成 $x_e$，按公式 (2) 拼接 Prompt。
4. 经冻结 Transformer 计算 Prompt 位置的输出平均值，再由共享分类器预测类别。

推断时**不会**执行匹配损失或反向传播，也**不会**使用训练阶段可选的频率加权公式 (4)。因此，论文真正解决的是“输入样本应当调用哪些知识”这一问题，而不是显式还原其任务编号。

**补充伪代码（从 Algorithm 1 的预测说明提炼）：**

```text
FUNCTION L2P_Predict(x, frozen_f, f_e, f_r, K, P, classifier):
    q ← frozen_f(x)[CLS_position]
    S ← TopNKeysByCosineDistance(q, K)  # 始终用基础检索
    x_e ← f_e(x)
    x_p ← Concat(P[S_1], ..., P[S_N], x_e)
    h ← Mean(f_r(x_p)[0 : N*L_p])
    RETURN Argmax(classifier(h))
```

与训练对照，推断使用的参数状态是已经学到的 $\mathcal P,\mathcal K,\phi$，而不是任务发生之前的初始状态。**推断公式不变，参数记忆已经改变**，这是理解连续学习阶段交接的关键。

## 八、实验设置、结果与设计依据

### 1. 数据集和所检验的能力

论文第 5 节及附录 C 使用四个连续学习基准；它们不是同一个数据集换名称，而是分别制造不同的任务转换条件。

| 数据集 | 论文中的学习设置 | 数据与任务的结构 | 主要检验点 |
|---|---|---|---|
| Split CIFAR-100 | 类别增量 | CIFAR-100 的 100 类划为 10 个任务，每任务 10 个不重叠类别 | 不知道任务 ID 时识别逐步增加的类别；任务之间存在一定视觉相似性 |
| 5-datasets | 类别增量 | CIFAR-10、MNIST、Fashion-MNIST、SVHN、notMNIST 五个数据集依次训练 | 来源和视觉分布差异更大时如何减少不必要的 Prompt 共享 |
| CORe50 | 领域增量 | 50 个物体、11 个采集领域；8 个领域训练，其余作为测试 | 类别目标相同而输入领域连续变化时的适应能力 |
| Gaussian scheduled CIFAR-100 | Task-agnostic | 各类别在训练批次出现的概率按高斯日程平滑改变，无明确任务边界 | 不依赖显式任务划分的连续更新能力 |

评估指标主要为 **Average Accuracy**（平均准确率，越高越好）与 **Forgetting**（遗忘程度，越低越好）。对于没有明确任务边界或只有一个测试集的设置，论文报告最终测试准确率。这里不从其他论文移植评估公式，避免把未在本文给出的细节当成本论文定义。

### 2. 训练配置及参数规模

论文第 5.2 节给出统一训练设置：预训练 ViT-B/16、Adam 优化器（$\beta_1=0.9,\beta_2=0.999$）、Mini-batch 大小 128、恒定学习率 0.03、输入分辨率 $224\times224$、像素归一化到 $[0,1]$、$\lambda=0.5$。对于有离散任务的类别增量和领域增量实验，每个任务训练 5 个 Epoch；task-agnostic 实验沿用相应协议，每个 Batch 只训练一次。

其主要 Prompt 配置为（**5-datasets 的完整 L2P 结果还使用了第 4.2 节的可选多样化 Prompt 选择策略**；这点在解读该数据集的消融结果时尤其重要）：

| 实验 | $M$ | $N$ | $L_p$ | Prompt + Key 参数数目（不含分类器） |
|---|---:|---:|---:|---:|
| CIFAR-100 相关设置、CORe50 | 10 | 5 | 5 | 46,080 |
| 5-datasets | 20 | 4 | 5 | 92,160 |

这一参数数目可以直接根据 Key–Prompt 结构核对。对 ViT-B/16 的 $D=D_k=768$，新增的池参数量为

$$
M(L_pD+D_k).
$$

例如 $M=10,L_p=5$ 时，$10(5\times768+768)=46{,}080$。这也说明为何论文称池参数非常小：新任务并未为每个任务再存储一份完整 ViT。**注意这些数字对应池中的 Prompt 与 Key，分类器仍有单独可训练参数。**

### 3. 主实验：不保存旧样本也能取得较高准确率

论文 Table 1 的无重放（buffer size = 0）结果如下：

| 方法 | Split CIFAR-100 平均准确率 ↑ | Split CIFAR-100 遗忘 ↓ | 5-datasets 平均准确率 ↑ | 5-datasets 遗忘 ↓ |
|---|---:|---:|---:|---:|
| EWC | 47.01 | 33.27 | 50.93 | 34.94 |
| LwF | 60.69 | 27.77 | 47.91 | 38.01 |
| **L2P** | **83.83** | **7.63** | **81.14** | **4.64** |

论文 Table 3 的 CORe50 领域增量实验中，无重放 L2P 测试准确率为 **78.33%**；Table 4 的 Gaussian scheduled CIFAR-100 task-agnostic 实验中，无重放 L2P 测试准确率为 **88.34%**。这些结果支持论文的经验结论：预训练主干结合动态 Prompt Pool，在多个设置下能显著减轻遗忘，同时不强制要求过去样本重放。

论文还提供配备旧样本缓存的 **L2P-R**，用于和基于重放的方法进行同条件比较。必须区分：**L2P 是不要求重放的基础算法；L2P-R 是额外加入重放的实验变体**，不能把后者的成绩说成零缓存成绩。实验结果也不能直接解释为对任意网络、任意数据流都有同样优势。

### 4. 关键消融：每个模块到底解决了什么问题

论文 Table 5 在 5-datasets 上依次去掉重要设计：

| 设计 | 平均准确率 ↑ | 遗忘 ↓ | 反映的问题 |
|---|---:|---:|---|
| 完整 L2P | **81.14** | **4.64** | Prompt Pool + 可学习 Key + 多样化选择共同作用 |
| 不使用 Prompt Pool，改为单个 Prompt | 51.96 | 26.60 | 所有任务共享同一 Prompt 时易产生严重干扰 |
| 不使用可学习 Key，用 Prompt 均值替代 Key | 58.33 | 20.45 | 检索表示与 Prompt 内容分离很重要 |
| 去掉多样化选择 | 62.26 | 17.84 | 对差异大的任务，过度共享 Prompt 会损害效果 |

这些消融支持的结论是**三个设计都对该实验设置的最终效果作出了重要贡献**，但它们并不是单因素的严格因果分解，更不能证明每个 Prompt 必然对应单一任务。尤其第三项多样化选择属于已知任务边界条件下的可选扩展，不应视作 task-agnostic L2P 必不可少的部分。

### 5. Prompt 选择分布说明什么

论文图 3 将不同任务选择各 Prompt 的频率画成直方图。Split CIFAR-100 中，不同任务来自同一原始数据集，具有较强的相似性，模型倾向于**跨任务共享更多 Prompt**；而 5-datasets 中不同数据来源差异较大，选择分布更偏向**任务特异的 Prompt 使用**。

这与方法的设计动机一致：不是希望所有任务总是隔离，而是让相似输入可以共享、差异输入尽可能减少无效共享。图 3 展示的是训练后观察到的**选择频率现象**，不是先验规定的硬性分配规则。

### 6. Prompt 超参数的影响

论文图 4 比较了 Prompt Pool 容量 $M$、每个 Prompt 的 Token 长度 $L_p$，以及一次选择的 Prompt 数量 $N$。

$M$ 决定系统总共能存储多少个可独立检索的 Prompt；$L_p$ 决定单个 Prompt 内部能容纳多长的可训练序列；$N$ 决定一次分类可以组合几个 Prompt。因此，**总池容量**与**单次推断注入的 Prompt Token 数 $NL_p$**是不同概念：增加 $M$ 并不必然增加一次前向的序列长度，而增加 $N$ 或 $L_p$ 会增加实际拼接的 Token 数。

图 4 显示，过短的 Prompt 通常性能不佳，而过大也未必带来改进；增大 Pool 对任务差异更大的 5-datasets 更有帮助，对 Split CIFAR-100 的收益较小。作者据此认为，在共享与任务特异知识之间，需要适当的 Prompt 容量与可选单元数量，而不是把这些超参数简单推到最大。

## 九、方法适用范围、局限与复现时的注意点

### 1. 方法实际依赖的前提

L2P 的一个关键前提是**存在可用的、性能较好的预训练序列模型**。因为连续训练主要优化 Prompt 和 Key，主干提供的基础表征质量会直接影响 Query 检索与最终分类。原论文在 ViT 上验证了方法，而非证明它能不加调整地应用到所有 ConvNet 或所有其他模态。作者在附录 B 中明确把扩展到其他架构与模态作为后续方向。

此外，论文 task-agnostic 实验使用 Gaussian scheduled CIFAR-100，它是人为构造的平滑分布变化协议。作者也指出，这与真实世界不规则、复杂的长期数据流仍有差距。因此不能把论文该组数据上的结果直接等同于已彻底解决真实环境的 task-free 连续学习。

### 2. 三种容易误读的“任务无关”

“测试时不需要任务 ID”说的是推断过程不读取一个外部给定的任务编号，并不表示 Prompt 不可能表现出任务偏好；相反，Prompt 的选择分布可以在统计上呈现任务相关性。“训练时不需要任务边界”说的是基础检索、分类和更新机制可以作用于连续的数据批次，并不表示任何任务边界辅助策略都能使用。最后，“不需要重放缓存”表示基础方法不以旧样本缓存为必要条件，并不表示任何历史信息都未被保存：**历史信息以训练后的可学习参数存在于 Prompt Pool、Key 和分类器中**。

### 3. Prompt 池不是一个永不覆写的档案库

在后续任务上，旧 Prompt 可以被再次选中并更新，分类器也会持续调整。没有重放或旧数据上的显式约束时，不能保证旧样本仍然得到原来的最优预测。L2P 的目标是通过冻结主干、输入驱动检索和局部参数更新来降低覆盖，而不是建立严格的不可遗忘证明。

另外，原论文强调 Key–Prompt 一一配对，训练时应让一个样本选中的 Key 与 Prompt 以相同索引参与计算；分类使用的是**Prompt 位置输出的平均值**。复现时如果错误地改成对图像全部 Token 平均、只用原始 `[class]` 输出，或者把 Key 直接拼接进 Token 序列，都会改变论文定义的算法。

### 4. 训练与推断中应当保持一致和区分的部分

| 检查点 | 训练阶段 | 推断阶段 |
|---|---|---|
| 计算 Query | 用未带 Prompt 的冻结预训练模型 | 相同 |
| 选择 Prompt | 公式 (3)，已知边界时可选公式 (4) | **始终公式 (3)** |
| 输入 Transformer | $[P_{s_1};\ldots;P_{s_N};x_e]$ | 相同 |
| 分类特征 | Prompt 位置输出的 AvgPool | 相同 |
| 结果 | 交叉熵 + Key 匹配损失 | 类别预测 |
| 更新 | $\mathcal P,\mathcal K,\phi$ 更新，主干冻结 | 全部参数不更新 |
| 历史经验 | 当前训练继续写入池参数 | 读取最终学到的池参数 |

这张表足以帮助检查实现是否遵循了论文的基本数据路径；但诸如初始化分布、频率表零值处理、特定代码库的批次平均方式等细节，原论文正文并未全部给出，不能凭经验声称一定是作者采用的原始做法。

## 十、完整方法链回顾

从系统真正执行的起点看，L2P 首先拥有一个**被冻结的预训练 ViT**，以及初始化的 **Prompt Pool、Key Pool、分类器**。当前任务的一张图像进入后，模型不先查询任务 ID，而是用不带 Prompt 的冻结网络生成 Query。Query 与所有 Key 比较，选出 Top-$N$ 个索引；这些索引定位相应的 Prompt Token。另一条路径将同一图像变为原始 Token 序列，两条路径在拼接环节汇合，然后经冻结 Transformer 处理。分类器读取 **Prompt 输出位置的平均池化表示**给出预测。

训练时，分类误差通过冻结 Transformer 的计算图回传到**选中的 Prompt 和分类器**，Key 的匹配误差更新**选中的 Key**。整个 Mini-batch 完成计算后，系统更新这些新增参数，保持预训练主干不变。下一批图像将在**已经更新的 Key–Prompt 空间**中重新检索；下一个任务到来时继续沿用上一任务的参数状态。推断时使用同一检索和分类路径，但不计算损失、不更新参数，也不要求任务身份。

因此，L2P 的贡献不是孤立提出“使用 Prompt”这一技巧，而是把**可学习的条件输入、可检索的 Key–Prompt 参数记忆、输入驱动的动态选择与连续优化**整合成一套能够跨任务复用的流程。论文实验进一步说明，这一机制在所测试的类别增量、领域增量与 task-agnostic 场景下能够有效缓解遗忘，同时避免把旧数据重放作为基础要求。
