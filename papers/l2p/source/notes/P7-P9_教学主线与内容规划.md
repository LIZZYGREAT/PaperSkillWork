## 一、三页的总体任务与前后衔接

## 二、P7：联合损失与参数更新——L2P 如何学会选择和使用 Prompt

### 1. 从 P6 的预测结果转入学习问题

P6 已针对训练样本 $(x,y)$，通过冻结 ViT 产生 Query $q(x)$，根据当前 Key Pool $\mathcal K$ 选出索引集合 $S(x)=\{s_1,\ldots,s_N\}$，取得相应 Prompt，构造扩展输入 $x_p$，经过冻结 Transformer 得到 Prompt 位置池化特征 $h(x)$，最终由共享分类器输出 Logits：

$$
z=g_\phi(h(x)).
$$

这一过程能够产生预测，但**能够执行前向传播不等于已学会正确分类与合理检索**。初始 Prompt、Key 和分类头仍需训练。本页的核心问题是：分类器和 Prompt 可以通过真实标签学习；Key 决定选取哪些 Prompt，却应当接受什么训练信号？

为了让读者理解训练机制，按**分类损失 → Top-$N$ 梯度限制 → Key 匹配损失 → 联合损失 → Batch 更新 → 下一 Batch 的状态变化**展开。

### 2. 分类损失使选中的 Prompt 与分类器适应当前样本

使用真实标签 $y$ 和 P6 产生的 Logits 计算 Softmax 交叉熵：

$$
\mathcal L_{\mathrm{cls}}(x,y)
=\operatorname{CE}\bigl(g_\phi(h(x)),y\bigr).
$$

分类器参数 $\phi$ 直接参与 Logits 计算，因此接收分类损失梯度。已选 Prompt $P_{s_i}$ 作为扩展输入 $x_p$ 的一部分，经由冻结 Transformer 影响 $h(x)$，所以分类损失同样能够对这些 Prompt 求导：

$$
\mathcal L_{\mathrm{cls}}
\longrightarrow g_\phi
\longrightarrow h(x)
\longrightarrow f_r(x_p)
\longrightarrow P_{s_1},\ldots,P_{s_N}.
$$

这里应直接调用 P3、P4 已讲过的结论：**冻结预训练权重不会阻断损失对 Prompt 输入的梯度**。无需再次推导 Attention 的 Q/K/V、Residual 与完整链式法则，只需要明确哪些对象处在当前损失的计算路径中。

当某个 Prompt 没有被此样本选中时，该样本的分类计算不使用它，因此不会由此样本的分类损失给它产生直接梯度。至此已解释 Prompt 内容怎样学习，但尚未解释 Key 怎样学习。

### 3. 硬 Top-$N$ 为什么不足以通过分类损失训练 Key

P5 的检索包含两个操作：先计算 $d_j=\gamma(q(x),k_j)$，再选出距离最小的 $N$ 个索引 $S(x)$。分类路径根据**离散索引**提取 Prompt，而不会将所有距离分数作为连续权重输入分类模型。

因此，在论文采用的这种硬 Top-$N$ 选择下，无法按普通连续可微算子的方式将分类损失直接穿过索引选择，获得能够平滑调整所有 Key 排序的梯度。此时分类损失主要在“**已选中哪些 Prompt**”这一结果已经确定的条件下，优化选中 Prompt 与分类器。

本段的教学重点应是**分清连续向量距离与离散索引选择**，而不是笼统宣称“检索不可学习”或“Key 完全不能求导”。距离函数本身可微，因此作者可以另行针对已选 Key 构造匹配损失。

### 4. Key 匹配损失：直接优化已选 Key 与 Query 的关系

论文为每个已选 Key 引入 Query–Key 距离项。沿用 P5 的余弦距离定义：

$$
\gamma(q,k)=1-\frac{q^\top k}{\lVert q\rVert_2\lVert k\rVert_2}.
$$

对当前样本，构造：

$$
\mathcal L_{\mathrm{match}}(x)
=\sum_{j\in S(x)}\gamma\bigl(q(x),k_j\bigr).
$$

此处 $q(x)$ 来自**没有插入 Prompt 的冻结 ViT**，是检索时使用的固定特征提取规则；选中 Key $k_j$ 为可训练参数。减小这项损失，会使 Key 的方向倾向于靠近当前 Query 的方向，影响后续样本与它的距离排序。

重要的因果关系是：**Key 的更新改变未来“谁更容易被选中”；Prompt 的更新改变未来“被选中之后如何影响分类”。** 二者通过共同的索引相互关联，但并不是从同一条梯度路径学习。

可用一个二维向量的教学示例说明距离变小时角度趋近。这个示例是辅助理解，不作为论文提出的额外学习规则。无需在主线中详细推导余弦距离对 Key 的梯度；若需要可放在次级知识说明中。

同时应避免误述：Key 匹配损失并不直接要求不同 Key 相互远离，不能保证给每个任务分配永久独立的 Prompt，也不能保证每次 Key 更新都改善所有样本的检索。

### 5. 合并两类损失：解释原论文公式 (5)

由于分类能力和检索能力都需要学习，原论文将两项损失结合：

$$
\boxed{
\mathcal L(x,y)=
\underbrace{\operatorname{CE}\left(g_\phi(h(x)),y\right)}_{\mathcal L_{\mathrm{cls}}}
+\lambda\underbrace{\sum_{j\in S(x)}\gamma\bigl(q(x),k_j\bigr)}_{\mathcal L_{\mathrm{match}}}
}
\tag{5}
$$

其中 $\lambda$ 控制 Key 匹配项的权重。优化对象为 Prompt Pool $\mathcal P$、Key Pool $\mathcal K$ 以及共享分类器的参数 $\phi$。冻结 ViT $f_e,f_r$ 不参与参数更新。

| 对象 | 主要直接训练信号 | 对后续流程的影响 |
| --- | --- | --- |
| 当前选中的 Prompt $P_j$ | 分类交叉熵 | 改变被选中后输入 Transformer 的条件向量 |
| 当前选中的 Key $k_j$ | Query–Key 匹配损失 | 改变未来 Query 的距离排序与选中集合 |
| 共享分类器 $\phi$ | 分类交叉熵 | 改变从池化特征到类别 Logits 的映射 |
| 冻结 ViT $f_e,f_r$ | 参数始终不更新 | 保留预训练表征与特征计算规则 |

这张表用于核对正文已经建立的机制，不能只给表格而省略 P7 前半部分对梯度来源的解释。特别应指明：**分类损失没有经硬 Top-$N$ 向 Key 提供通常意义上的连续梯度；匹配损失直接对已选 Key 可微。**

### 6. 一个 Mini-batch 内如何汇总损失与更新参数

前文以单个样本解释了两项损失，但原论文附录 Algorithm 1 按 Mini-batch 完成一次训练更新。设当前 Batch 为 $\mathcal B=\{(x_i,y_i)\}_{i=1}^{B}$，每个样本都依据同一个**批次更新前**的 Key–Prompt 状态独立检索并计算损失。

论文算法将样本损失累积为：

$$
\mathcal L_{\mathcal B}=\sum_{i=1}^{B}\mathcal L(x_i,y_i).
$$

实践中具体的损失归约可随实现处理，但论文 Algorithm 1 的伪代码表述为累积损失，不应直接将平均作为论文确定的唯一操作。

为说明联合更新，可采用以下**补充教学示例**：一个包含两个样本的小批次，$N=2$，其中

$$
S(x_1)=\{1,3\},\qquad S(x_2)=\{3,5\}.
$$

$P_3$ 同时参与两个样本的分类计算，因此当前 Batch 中针对 $P_3$ 的分类梯度由两个样本的贡献合成；$P_1$ 和 $P_5$ 分别参与其中一个样本。相应的 $k_1,k_3,k_5$ 根据选中它们的样本计算匹配梯度。未被本 Batch 使用的 Key/Prompt 没有来自这些样本的直接损失梯度。分类器接收整个 Batch 的分类梯度。

执行顺序应固定为：**每个样本检索与前向 → 每个样本计算损失 → Batch 累积 → 反向传播 → 一次优化器更新**。不能表现成“处理第一张图就立即更新池，再处理同一 Batch 的第二张图”。

对更新位置可写成抽象形式：

$$
(\mathcal K_b,\mathcal P_b,\phi_b)
\xrightarrow{\mathcal B_b\text{ 的反向传播与优化}}
(\mathcal K_{b+1},\mathcal P_{b+1},\phi_{b+1}).
$$

原论文附录 Algorithm 1 用梯度下降步写出 Key、Prompt 和分类器的参数更新；第 5.2 节则指出实验使用 **Adam**。这些符号用于说明状态依赖，不代表作者实验使用纯 SGD，也不在本页展开 Adam 内部优化器状态。

### 7. 本页收束：参数更新怎样影响下一次检索与分类

完成当前 Batch 后，下一批样本仍由冻结 ViT 计算 Query，因此在相同输入与预处理下，Query 特征提取规则保持不变；但用于比较的 Key 已更新，所以 Top-$N$ 结果可能变化。已经学到的 Prompt 也发生变化，因此即便下一次仍选中同一组合，输出 Logits 仍可能不同；共享分类器的更新也会影响结果。

这里必须把**“记忆内容发生变化”**与**“记忆的寻址关系发生变化”**联系起来，形成完整单 Batch 的学习闭环。

**本页交付给 P8 的问题：**

> 一次 Batch 已经能够更新 Key、Prompt 和分类器；当数十、数百个 Batch 以及不同任务依次到来时，这些参数如何持续继承，最终形成能够识别旧类与新类的完整模型？

### 8. P7 的内容边界

不再从头讲 ViT、Attention、Prompt 拼接和 Prompt 位置池化；这些已经由 P2–P6 完成。P7 只使用必要的前向结果来解释损失、梯度、Batch 累积和可训练状态变化。跨任务循环、完整训练伪代码及最终推断由 P8 负责；论文的可选历史频率检索与实验依据由 P9 负责。

## 三、P8：完整训练、跨任务继承与最终推断

### 1. 从单次更新转入真实的连续学习过程

P7 已经说明一个 Mini-batch 如何选取 Prompt、计算两项损失并更新参数。但连续学习的特点在于新数据不断到来，当前更新必须与此前的参数状态相连，也必须成为下一轮学习的起点。

因此 P8 应完全以**实际执行顺序**展开，而不重复列举各模块的静态职责：初始参数是什么，第一批数据做了什么，损失产生后哪些状态改变，下一批数据如何使用新状态，任务转换时留下什么，最后如何预测。

本页是整篇教程的**算法贯通环节**，依据应直接对齐原论文附录 D 的 Algorithm 1。

### 2. 初始化：区分固定的预训练能力与待学习参数

训练开始前，已有一个预训练好的 ViT，其输入嵌入层 $f_e$ 与 Transformer Encoder $f_r$ 被冻结。系统另外初始化 $M$ 个 Prompt $\mathcal P_0$、对应的 $M$ 个 Key $\mathcal K_0$ 和共享分类器参数 $\phi_0$，并配置 $M,N,L_p,\lambda$ 等超参数与优化器。

为追踪持续变化的状态，可将可训练参数记为：

$$
\Theta_0=(\mathcal P_0,\mathcal K_0,\phi_0).
$$

$\Theta_b$ 是本笔记为表述方便引入的“第 $b$ 次更新后的可训练参数状态”，**不是原论文的额外模块**。冻结的 ViT 保持同一套权重，不需要每轮重新初始化，也无需为任务预先指定专属 Prompt。

这一阶段不依赖历史样本缓存。基础 L2P 不需要 Replay Buffer；后续讨论的 L2P-R 则是另外配置了重放的实验变体。

### 3. 第一个任务：从第一个 Mini-batch 建立完整运行闭环

当任务 $\mathcal D_1$ 到来时，系统从当前数据取得第一个 Mini-batch。对于 Batch 内每个样本 $(x,y)$，先由无 Prompt 的冻结 ViT 提取 $q(x)$，在当前 Key Pool 中查找 Top-$N$，获取对应 Prompt；同时生成图像 Token，与选中的 Prompt 拼接，经过冻结 Transformer 得到 Prompt 位置输出的平均特征，最后由共享分类器计算 Logits。

每个样本产生分类交叉熵与 Key 匹配损失，Batch 内损失汇总后执行反向传播与优化器更新。更新完成，系统得到新的 $\Theta_1$。

下一 Batch 直接以 $\Theta_1$ 为起点，重复相同的操作，并得到 $\Theta_2$。这说明 Key 的变化能够改变后续检索，Prompt 的变化能够改变被调用时的分类表现，分类器的变化继续影响所有输出。

要特别明确**Batch 的更新边界**：同一 Batch 中的样本先基于当前参数计算，聚合损失后统一更新。每个 Batch 完成后才把更新后的状态交给后续 Batch。

### 4. 一个任务训练结束后，如何进入下一个任务

在具有显式任务划分的实验中，每个任务会按照设置执行若干 Epoch。假设任务 $t-1$ 结束后保存的可训练参数为：

$$
\Theta^{(t-1)}=(\mathcal P^{(t-1)},\mathcal K^{(t-1)},\phi^{(t-1)}).
$$

当任务 $t$ 到来时，直接沿用这套参数，继续处理当前任务 $\mathcal D_t$：

$$
\Theta^{(t-1)}
\xrightarrow[\text{仅使用当前阶段可用训练数据 }\mathcal D_t]
{\text{多 Batch 检索、分类与更新}}
\Theta^{(t)}.
$$

这部分是跨任务状态解释的重点。新任务到来时，**既不重建 Prompt Pool，也不将已经学过的 Key 恢复成初始值**。历史使用过的 Prompt 可能重新被选中并继续优化，历史上少用或未用的 Prompt 也可能参与当前训练。共享是样本级、动态且允许重叠的。

可延续一个小型**补充教学示例**：任务 A 的某个样本选择 $\{P_1,P_3\}$，随后任务 B 的样本选择 $\{P_3,P_5\}$。$P_3$ 受到两阶段样本的更新，$P_1$ 不因任务 B 这个样本产生直接分类梯度，$P_5$ 则参与任务 B 的当前计算。这个例子只说明参数作用范围，不能推导出 $P_1$ 永远属于任务 A，或不重叠的 Prompt 能保证完全没有遗忘；共享分类器仍持续更新。

### 5. 依据 Algorithm 1 串联完整训练伪代码

正式算法的展示应与论文附录 D 对齐：外层处理连续任务，中层处理各训练 Epoch，内层处理 Mini-batch，Batch 内每个样本独立选择 Prompt，计算损失，最后更新已选 Key/Prompt 与共享分类器。基础流程可整理为：

```text
ALGORITHM L2P_Train
INPUT:
    预训练并冻结的输入嵌入层 f_e、Transformer Encoder f_r
    连续任务数据 D_1, ..., D_T
    Prompt 数量 M、选择数量 N、单个 Prompt 长度 L_p
    损失权重 λ、各任务训练轮数 E_t、优化器

INITIALIZE:
    初始化 Prompt Pool P[1..M]、Key Pool K[1..M]、分类器 φ
    冻结 f_e 与 f_r

FOR t = 1 ... T:
    FOR epoch = 1 ... E_t:
        FOR EACH mini-batch B from D_t:
            batch_loss ← 0
            selected_in_batch ← ∅

            FOR EACH (x, y) in B:
                # 无 Prompt 的检索路径
                q ← FrozenViTWithoutPrompt(x).CLS
                S ← TopNByKeyDistance(q, K)           # Eq. (3)

                # 带 Prompt 的分类路径
                x_e ← f_e(x)
                x_p ← Concat(P[S[1]], ..., P[S[N]], x_e)  # Eq. (2)
                H ← f_r(x_p)
                h ← Mean(H[0 : N*L_p, :])
                logits ← g_φ(h)

                # 分类与检索匹配目标
                loss_cls ← CrossEntropy(logits, y)
                loss_match ← Sum(Distance(q, K[j]) FOR j in S)
                batch_loss ← batch_loss + loss_cls + λ * loss_match
                selected_in_batch ← selected_in_batch ∪ S

            Backward(batch_loss)
            OptimizerStep(selected Key/Prompt parameters, φ)
            # 预训练 f_e 与 f_r 权重不更新

    # 继续保留此时的 P、K、φ，供后续任务训练

OUTPUT:
    冻结的 f_e、f_r 与训练后的 P、K、φ
```

该伪代码为**依据原文 Algorithm 1 整理的教学表达**，其中 `FOR EACH mini-batch` 将原文的批次抽样操作展开成整轮训练的常见迭代表示；`OptimizerStep` 省略 Adam 的内部计算。这里的 `selected_in_batch` 对应原文收集已选 Key/Prompt 的集合。若在已知任务边界的实验中启用原论文可选策略，训练时可用 Eq. (4) 代替 Eq. (3) 的 Top-$N$ 评分方式；该扩展的具体动机与约束在 P9 再讲。

建议正文与这段伪代码相互对应，但不逐行重复解释：正文解释为何必须跨 Batch/任务继承状态，伪代码负责固定各操作的执行顺序。

### 6. 没有明确任务边界时，算法为什么依然能运行

前面使用任务 $\mathcal D_1,\mathcal D_2,\ldots$ 只是为了清楚描述有边界的连续学习实验。基础 L2P 的单个 Batch 并不使用任务 ID 查询专属 Prompt，而是依赖图像产生 Query，按当前 Key 距离选择 Prompt。因此，当数据分布随时间连续变化、没有明确任务分界信号时，仍可按到达顺序持续对 Batch 执行同样的更新：

$$
\Theta_b\xrightarrow{\mathcal B_b}\Theta_{b+1}
\xrightarrow{\mathcal B_{b+1}}\Theta_{b+2}.
$$

原论文在 task-agnostic 设置下每个 Batch 只训练一次。必须区分：**不需要任务边界的基础检索与更新**，不表示带有历史任务频率 $H_t$ 的可选训练策略也能直接用于无边界数据流。

### 7. 最终推断：未知任务身份下如何直接输出类别

训练完成后，系统拥有冻结的 ViT，以及已经从连续数据中学到的 $\mathcal P^*,\mathcal K^*,\phi^*$。给定测试图像 $x$，不再提供真实标签，不执行任何损失计算或参数更新；系统仍然按输入内容检索 Prompt，再用同一分类路径预测：

```text
ALGORITHM L2P_Predict
INPUT: 测试图像 x；冻结 ViT；训练后的 P、K、φ

q ← FrozenViTWithoutPrompt(x).CLS
S ← TopNByKeyDistance(q, K)                # 始终 Eq. (3)
x_e ← f_e(x)
x_p ← Concat(P[S[1]], ..., P[S[N]], x_e)
H ← f_r(x_p)
h ← Mean(H[0 : N*L_p, :])
logits ← g_φ(h)
RETURN Argmax(logits)
```

检索并不需要先预测“这是任务几”；它直接返回当前图像对应的一组 Prompt。即使训练过程中启用了可选的历史频率加权，**推断阶段仍按原论文 Eq. (3) 执行普通 Query–Key 检索**。训练与推断的参数状态不同，检索与分类的基本数据路径一致；推断没有 Batch Loss、反向传播和参数更新。

P8 在此完成从初始化到推断的完整流程。应让读者能够独立回答：当前阶段持有哪些参数、每轮改变哪些状态、下一轮为何使用新状态，以及最终为何无需任务 ID 仍能选择 Prompt。

## 四、P9：设计选择与实验验证——L2P 的效果来自哪里

### 1. 从算法中的共享现象提出新的设计问题

到 P8 为止，已经知道不同任务的样本可能选择同一批 Prompt。这样的共享可能让相近输入复用已学知识，但对于差异较大的任务，也可能使少数 Prompt 被反复选中和修改，形成不必要的干扰。

由此引入一个额外设计问题：**当训练数据有明确任务边界、且任务之间差异较大时，能否利用先前的 Prompt 使用情况，鼓励新任务探索其他 Prompt？**

这为原论文第 4.2 节的可选 **Diversified Prompt Selection（多样化 Prompt 选择）**建立了自然动机。该策略应在基础算法和跨任务共享讲清楚以后再出现，不能在 P5 中被误认为所有 L2P 运行场景都必需的检索步骤。

### 2. 可选的多样化选择：利用历史频率改变训练期检索

论文针对训练时已知任务边界的情况，维护一个 Prompt 选择频率表：

$$
H_t=[h_1,h_2,\ldots,h_M],
$$

其中 $h_j$ 是此前任务（至任务 $t-1$）中 Prompt $P_j$ 被选择的归一化频率。为了降低历史上高频 Prompt 在新任务中被持续使用的倾向，论文将原本仅依据距离的选择目标改为公式 (4)：

$$
S(x)=
\underset{\substack{S\subseteq\{1,\ldots,M\}\\|S|=N}}{\arg\min}
\sum_{j\in S}\gamma(q(x),k_j)h_j.
\tag{4}
$$

这是对**训练阶段选择规则**的调整：按历史频率对当前 Query–Key 距离加权，再选最小的 $N$ 项。其设计意图是惩罚被频繁使用的 Prompt，鼓励差异大的任务采用更加多样的组合。频率统计不是一个新的可微 Key，也不是预测任务 ID 的额外分类器。

必须明确三个边界：

1. 该策略利用已知的**训练任务边界**和过去选择统计；基础 L2P 在 task-agnostic 情况下仍使用 Eq. (3)。
2. **测试时始终用 Eq. (3)**，不使用频率表加权，不需要任务 ID。
3. Eq. (4) 仅改写 Prompt 选择的评分；原论文 Eq. (5) 中的 Key 匹配项仍按选中 Key 的 $\gamma(q,k_j)$ 计算，不擅自把损失改成带频率权重的形式。

原论文未在这一数学描述中完整确定所有初始化、零频率及数值稳定化实现细节。若未来需要严格代码复现，应核对作者实现，不能自行设定后宣称属于原论文原始算法。

### 3. 用 Prompt 使用直方图验证共享方式

在解释频率策略后，引入原论文第 7 页 **Figure 3**。图中分别统计不同任务选择各 Prompt 的频率。它所提供的是训练后观察到的**选择分布证据**，不是预先规定的“Prompt–任务身份对应表”。

论文观察到，Split CIFAR-100 来自同一原始数据集，任务间有较强的视觉相似性，因此不同任务倾向于共享较多 Prompt。5-datasets 包含差异较大的数据来源，Prompt 使用则表现出更强的任务特异性。

这与 L2P 的设计目标一致：相近输入允许复用记忆，不相近输入可以减少部分不必要的共享。但不应由直方图直接断定“每个 Prompt 只属于一个任务”，也不能忽略 5-datasets 的完整方法配置**使用了可选的多样化选择策略**；图中分布是该实验设置下的观察结果。

### 4. 消融实验：逐项核对组件是否确实有用

原论文第 7 页 **Table 5** 在 5-datasets 上比较完整 L2P 与移除核心设计后的结果：

| 5-datasets 配置 | 平均准确率 ↑ | 遗忘 ↓ | 对应此前的教学问题 |
| --- | ---: | ---: | --- |
| 完整 L2P | **81.14** | **4.64** | 多 Prompt、可学习 Key 与多样化选择共同工作 |
| 不使用 Prompt Pool（单 Prompt） | 51.96 | 26.60 | P4：单 Prompt 仍易受到新旧任务干扰 |
| 不使用独立可学习 Key（用 Prompt 均值替代） | 58.33 | 20.45 | P5：检索表示与 Prompt 内容分离的重要性 |
| 去掉多样化选择 | 62.26 | 17.84 | P9：在任务差异较大时鼓励更丰富的 Prompt 使用 |

这里的解释应当逐项回扣 P4、P5 和本页新介绍的策略：

- **移除 Prompt Pool：**所有任务集中更新单一 Prompt，更容易出现参数冲突，性能明显下降。
- **移除独立 Key：**不再分别优化检索向量和实际注入的 Prompt 内容，结果变差，支持 Key–Prompt 分离的设计。
- **移除多样化选择：**在 5-datasets 的条件下，取消历史使用频率引导后性能下降，说明该可选扩展在此设置中具有实际作用。

Table 5 是在特定基准和实现配置下得到的消融，**不能被解释为每个组件在所有数据集上的独立、恒定因果贡献**，更不能作为严格无遗忘的证明。

### 5. 主实验：基础 L2P 能否在不重放旧样本时持续分类

首先回到 P1 的研究约束：新任务持续到来、旧任务仍要预测、推断时不知道任务 ID。原论文第 6 页 **Table 1** 的零回放（Buffer size = 0）部分提供了具有代表性的类别增量结果：

| 方法 | Split CIFAR-100 平均准确率 ↑ | 遗忘 ↓ | 5-datasets 平均准确率 ↑ | 遗忘 ↓ |
| --- | ---: | ---: | ---: | ---: |
| EWC | 47.01 | 33.27 | 50.93 | 34.94 |
| LwF | 60.69 | 27.77 | 47.91 | 38.01 |
| **L2P** | **83.83** | **7.63** | **81.14** | **4.64** |

这组结果表明：在论文的实验协议与预训练模型条件下，L2P 在不要求历史样本重放的情况下取得了较高的持续学习准确率，并显著降低了这些对照方法中的遗忘指标。需要注意：比较是**同一数据集、同一协议内的方法对照**，不能跨不同数据集直接比较数字高低。

之后可以补充原论文 Table 3、Table 4，以说明方法适用范围不局限于类别增量：

| 实验设置 | 数据集 | 无回放 L2P 测试准确率 |
| --- | --- | ---: |
| 领域增量 | CORe50 | 78.33% |
| Task-agnostic | Gaussian scheduled CIFAR-100 | 88.34% |

这些结果用于验证同一方法可以处理同类目标下的领域变化，以及没有明确任务边界的合成连续数据流。但其指标与类别增量的 Average Accuracy/Forgetting 并不完全等同，不能将这几组百分数直接排名。

原论文还提供带旧样本缓存的 **L2P-R**，用于与部分重放方法在相同缓存规模下比较。应明确区分：**L2P 基础方法不要求重放；L2P-R 是额外结合重放的实验变体。** 不可把 L2P-R 的结果当作零缓存 L2P 的成绩。

### 6. 超参数分析：池容量与单次调用容量是不同概念

原论文第 8 页 **Figure 4** 考察三个关键超参数：

$$
M=\text{Prompt Pool 中的 Prompt 总数},\qquad
L_p=\text{单个 Prompt 的 Token 数量},\qquad
N=\text{单次选择的 Prompt 数量}.
$$

其中本次实际拼接的 Prompt Token 数为 $NL_p$；全部 Prompt 的可训练 Token 参数数量则与 $ML_pD$ 成正比（独立 Key 还增加约 $MD_k$ 个参数）。因此，增加池容量 $M$ 不必然增加一次前向的序列长度，而增加 $N$ 或 $L_p$ 会改变每次实际输入的 Token 数量。

Figure 4 的结果表明，这些超参数并非越大越好：过短 Prompt 往往不足，而过大或过多的组合也未必持续提升准确率。任务差异较大的数据集，对更充足的 Pool 容量可能有更明显的收益。这里只需把实验趋势与已理解的容量概念对齐；完整参数热力图不需要另辟一页重复讲解。

### 7. 结尾：带着证据回答 P1 的研究问题

P1 提出的问题是：在顺序数据到来、无法始终访问旧样本、测试时不能依赖任务 ID 的条件下，怎样持续学习并缓解灾难性遗忘？

经过 P4–P8，读者已理解完整计算机制：冻结预训练 ViT 保留共享表征能力；Prompt Pool 作为持续学习的可训练条件参数；Query–Key 检索让每个样本选择自己的 Prompt 组合；分类损失与 Key 匹配损失分别学习 Prompt 内容和检索关系；新任务直接继承此前参数，推断时按输入内容完成选择和分类。P9 的使用频率、消融与主实验为这套设计在论文评测设置中的有效性提供证据。

同时应保留合理的结论范围：Prompt 与分类器仍可能受到新任务更新影响，L2P 是**缓解遗忘**而非保证永不遗忘；其效果依赖可用的预训练序列模型，论文关于 task-agnostic 的 Gaussian scheduled CIFAR-100 仍是合成协议。无需在结尾再次完整演示训练流程。
